The lane's anchored tool bytes do not exist yet (`arm=absent`), so these attacks bind
to the contract's frozen interface and were executed against my scratch synthetic
implementing that interface exactly (same `contains_value` boundaries as the r82
carrier side). Fixture skeleton as in C3.4; each attack changes rev A's bytes.

| attack | what the code does | what it should do | observed |
|---|---|---|---|
| 4a `row_contains="Row"` is a substring of another row's text (`Note about Rows` row carries 19 and sorts first; anchored `Row A` states 18) | existential per-line: any anchor-carrying line with the token passes | anchor must identify the pinned row: first-match parity with the carrier side (r82 `stated_value` breaks at the first anchor row) or flag non-unique anchors | `rc=0`, no mismatch — **bypass** |
| 4b two rows carry the anchor with conflicting values (`Row A` 18, `Row A (old)` 19) | existential finds the matching row | all anchor-carrying rows must state the value (universal), or first-match | `rc=0` — **bypass** |
| 4c anchored row's value cell states 18 but the same line mentions `row_tally=19` in prose | token is on the anchor line → passes | per frozen interface this passes; only cell-level pinning would catch it — a documented same-line limitation (same class the r82 spotcheck named) | `rc=0` — **bypass (documented-limitation class)** |
| 4d token as prefix of a larger number (`row_tally=190`, value 19) | `(?![\w.-])` boundary blocks `19` inside `190` | flag (no exact token on the anchored row) | `rc=1 REVISION_MISMATCH … rev-bytes` — safe over-strict |

Exact output:

```text

4b two-anchor-rows rc=0 mismatches=NONE
4c same-line-prose rc=0 mismatches=NONE
```

**Surviving bypasses to name:** 4a and 4b are closed if the landed tool evaluates the
**first** anchor-carrying row (deterministic, matching the r82 carrier-side
`stated_value` semantics) or requires **every** anchor-carrying row to state the value;
under a literal existential reading ("on one and the same line … both") both stay
green. 4c survives any line-scoped test and is only addressable by pinning the cell;
it belongs in the tool's documented limitations, not the kill rule. 4d/4e are safe
directions (over-flagging, never under-flagging).

**Additional defect in the frozen counter's fixture wiring:** `fixture_run` and the
real-lane run both pass `--root repo --git repo` with the **same directory**
(count-c3.py:155-156 and :277-278), so a tool that resolves revision bytes from the
worktree instead of the git object store (the r82 `rev_against_root` mutant class, r82
probe coverage finding #26) would still pass both fixtures. The r82 probe recommended
splitting `--root` (plain worktree copy) from `--git` (the repo); the frozen counter
did not adopt that split — the wiring remains selftest-blind end-to-end.
