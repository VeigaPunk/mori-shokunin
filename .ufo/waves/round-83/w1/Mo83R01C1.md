## 5. Why `red_detector_never_passes` is sound (my two attacks on it, both refuted)

`detector_repo()` might fail and fail the arm for the wrong reason, or fail the **pristine** copy
(pristine=red ⇒ unmet forever). Refuted: the committed `detector_repo()` (c1 :178-188) verifies a
real checkout (`git rev-parse --verify HEAD`) before trusting `here`, else falls back to the lane
checkout at `~/Projects/shokunin/mori-shokunin` (:188). Instrumented single-copy selftest: one
doctored process, 2.6 s total, `PASS red_detector_never_passes doctored rc=1 detector-line=True
rev=c4845c832443`, `pass=10 fail=0`.

Suspicion 2 (unbounded recursion: the doctored `<rev>` run grades bytes that contain the arm ⇒
chains of nested doctored runs). Refuted by replication: the doctored copy is a copy of **the r82
counter**, whose `<rev>` mode grades the **r82 11-mutant population over r80/r81 counter bytes —
none of which contain the arm**. Manual run of the doctored copy at the tip:


So the arm is a true main-path discriminator: real gate ⇒ doctored rc 1 + `detector=red`; mutant
gate (`return 0 if met else 1`) ⇒ doctored rc 0 because the r82 population is still 11/11 killed
at the tip (met True). The kill is honest and the design terminates. Residual coupling: §7.1.
