## Method

Mutants are generated by `<scratch>/mutate.py` from the frozen v5 bytes; every anchor
string is asserted to occur exactly once; every mutant parses under `ast`; unified
diffs are kept at `<scratch>/out/<name>.diff` and reproduced below. Before hash
(pristine) = `35c69d91…`; after hash per mutant in the table.

Detectors (run for pristine and every mutant):

1. Kill criterion (the verdict): `TMPDIR=<scratch>/tmp python3 <mutant> --selftest`
   — killed iff exit non-zero. Baseline: rc=0, `PIN_CHECK_SELFTEST pass=119 fail=0`
   (matches the witness receipt `pass=119,fail=0`).
2. Arm C by hand: `<scratch>/armc.py` replicates the frozen `count-c1.py`
   `arm_classified()` verbatim — builds the five-row fixture (`enva/envb` env pair,
   `stla/stlb` stale pair, `okay` match), runs `python3 <tool> --root <fixture>
   --timeout 60` with per-run TMPDIR, and applies the counter's checks exactly:
   env lines end `class=env`, stale lines end `class=stale`, `okay` is a class-less
   match, last line starts `PIN_CHECK=unmet` and ends ` env=2 stale=2`.

## Survivor analysis (coverage findings)

### m05 — no detector pins a line-count class
Neither the selftest (no arm checks the `stale` count of a `kind=lines` mismatch) nor
the frozen five-row fixture (no line-count pins) exercises the line-count class. Hand
probe (`miniarms.py` armL; fixture: honest tally row + `(99 lines)` overpin on
`tools/foo.py`, 5 observed lines):
- pristine: `pin line=3 kind=lines state=mismatch pinned='99 lines' file=tools/foo.py observed=5 class=stale`
  → summary `PIN_CHECK=unmet … env=0 stale=1` (env+stale=mismatches holds).
- m05: identical `kind=lines` line, but summary `PIN_CHECK=unmet … env=0 stale=0`.
So the mutant breaks P-C1's summary invariant `env + stale = mismatches` silently; the
mismatch is still reported and `met` is still false, but the class accounting is wrong.

### m06 — the selftest never exercises the default scratch parent
The only `--rev` success arm (`v5_rev_export_outside_repo`) passes `--scratch xs`
explicitly, so the default (`tempfile.gettempdir()`) is never the thing under test;
reverting the default to `<repo>/.scratch` keeps all 119 arms green. Direct evidence
of the defect (mini arm A, faithful copy of the frozen `arm_kill()`; fixture with
120,000 files so the `--rev` clone/checkout is still writing when the kill lands):
- pristine: `ARM_A_KILL started=True residue=0 exit=-9` — SIGKILLed mid-export into
  scratch ⇒ the repo it reads stays clean (0 status lines).
- m06: `ARM_A_KILL started=True residue=1 exit=-9`, first residue line
  `?? .scratch/pin-check-4pdkgygj/tree/` — the export lands inside the repo it reads;
  a kill left a nonzero residue, i.e. the frozen counter's arm A (`kill_residue`)
  fails. (Also observed: after a *completed* m06 run, `<repo>/.scratch` exists.)

### m07 — the selftest has no pinned instrument that reads git objects
The clone-export change exists precisely because instruments like
`.ufo/waves/round-49/count-c1.py` and `conform.py` read git objects from the tree
they run in; the selftest's synthetic trees contain no such instrument, so reverting
to `git archive` keeps all 119 arms green. Mini arm B (faithful copy of the frozen
`arm_relocated()`: fixture whose pinned instrument runs `git rev-parse HEAD` in its
own tree; tool run under bubblewrap with the lane path `--tmpfs`-hidden; `--scratch`
explicit):
- pristine: `ARM_B_BWRAP rc=0 last=PIN_CHECK=met …` (shared clone has its own `.git`).
- m07: `ARM_B_BWRAP rc=1 last=PIN_CHECK=unmet … mismatches=1 …` (archive tree has no
  `.git`; instrument prints no tally ⇒ `class=env` mismatch) — i.e. the frozen
  counter's relocated arm (B) fails.

## Named limits (counter weaknesses found — frozen, not proposed for change)

- The C1 counter's arm A is timing-dependent (contract-named limit): its 3 s
  kill window misses repos whose export finishes faster. Reproducing it faithfully
  required a 120k-file fixture; a 4k-file fixture exported in 0.14 s and the watcher
  saw `started=False` even for the mutant.
- Arm C's five-row fixture contains no digest or line-count pins, so m04, m08 and
  m10 pass arm C while being killed by the selftest — for those three the selftest
  is the strictly stronger detector; the opposite is true for m06/m07.
- The selftest's only `--rev` success arm passes `--scratch` explicitly, leaving the
  default scratch parent (the very thing the kill-residue arm protects) untested.

## Findings

- F1 (MED): the selftest never exercises the default `--scratch` parent; m06
  (default reverted to `<repo>/.scratch`) survives 119/119. The frozen counter's arm
  A is the only detector; a faithful SIGKILL probe shows residue in the read repo
  (1 status line `?? .scratch/pin-check-…/tree/`) vs 0 for pristine. Concerns
  `tools/mori-pin-check.py` `main()` (`scratch_parent` line, data commit) and the
  selftest arm `v5_rev_export_outside_repo` (always passes `--scratch`).
- F2 (MED): the selftest has no git-object-reading pinned instrument; m07 (archive
  export, v4 body) survives 119/119. The frozen counter's relocated arm (B) is the
  only detector: under bwrap with the lane hidden, m07 yields `PIN_CHECK=unmet`
  mismatches=1 rc=1 vs pristine `PIN_CHECK=met` rc=0. Concerns `export_rev()`.
- F3 (MED): neither the selftest nor arm C's fixture pins a line-count class; m05
  survives 119/119 and arm C ok. The summary invariant `env+stale=mismatches` breaks
  silently (hand probe: `… env=0 stale=0` with a `kind=lines state=mismatch` present).
  Concerns the `check()` line-count branches.
- F4 (LOW): the "env ⇒ not met" rule has a larger blast radius than the two v5 env
  arms: m10 also broke the `timeout` and `v2_disagreeing_tally_lines` arms, i.e. any
  future weakening of the env-mismatch accounting affects four arms, not two.
- F5 (LOW): reproduction sensitivity of the counter's arm A: a 4k-file fixture
  completes its export in ~0.14 s (below the watcher's window) — arm A's 3 s window
  after "first visible write" needs a slow-enough export to observe residue.
