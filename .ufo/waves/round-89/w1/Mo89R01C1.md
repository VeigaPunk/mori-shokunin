## Defects (named)

1. **Harm: over-refusal of valid equivalents (13 cases, table above).** Cause: script position is
   `index 1` or `index 2 when tokens[1] startswith "-"`. Any option with a value or a wrapper before the
   interpreter (`-W ignore`, `--`, `-I -B`, `env`, `nice`, `exec`, `uv run`, `bash -c`), any
   interpreter name other than the 6-item allowlist (`python3.14`), any `&&` join, and any `;` inside
   quotes (`shlex` error → refused) fails. The registry limit row names only wrappers and naive
   `;` splitting; the `-I -B`, `python3.14`, `env`-prefix, `--`, `-W` and `&&` cases are not declared.
2. **Residual attack: flag-value lookalike still accepted with a clean verdict (A03, A04, A12).** The
   script-position rule treats `tokens[2]` as the script whenever `tokens[1]` starts with `-`. `-W`, `-X`,
   `-c`, `-m` take a value, so the bound path is taken as an option argument, not as the executed script,
   and the `-c` code prints the exact body. Result: a selfprint receipt with the bound path bound clean.
   The frozen `selfprint` fixture (path after `-c "..."`) is refused, so the predicate does not see this.
3. **Residual, binder-only: `-c`/`-m` value lookalikes (A05, A06)** pass the binder; replay fails, so no clean
   verdict, but the binder's acceptance rule is wrong in the same way as (2).
4. **Interpreter identity by basename only.** Any `*/python3` passes the script-position rule (not exercised
   beyond reading `script_position`; no attack run).
5. **Legibility (contract item):** the driver shows `FX comment accepted problems=cmd-binding` for a
   refusal. In `count-c1.py` `FX <kind> accepted|refused` reports whether the expectation held, not whether
   the receipt was accepted; the wording reads as if the refused fixture were accepted.
