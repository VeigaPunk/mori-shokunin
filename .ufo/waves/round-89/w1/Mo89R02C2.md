## 5. Attribution and kill-rule review (static, frozen `count-c2.py`)

Checked the code path `grade()`, `killed()`, `unattributed()`, `arm_failed()`, `red()`, `green()`, `arms_of()`, `selftest_run()`, `main()`.

- **Kill rule.** `killed = red(rc,out) and arm_failed(out, declared)`; `arm_failed` = `^FAIL <arm>(\s|$)` with re.M; `red` = `rc != 0 or \bfail=[1-9]\d*\b`. Matches the frozen `killed ⟺ (rc≠0 ∨ fail>0) ∧ FAIL <declared arm>`. Boundary arm `arm_boundary` covers `FAIL own_ok_red2` (not matched) and `PASS own_ok_red` (not matched). Survivors/unattributed/unanchored/empty/pristine are classified and set `met` false. No path found where a red run without the declared FAIL line counts as killed. **No false-kill path found in the frozen rule as written.**
- **Declared-arm identity.** Each mutant's `arm` is compared against the mutated copy's own FAIL lines only; the per-file `pristine` check (`green` + exact arm count, `ARMS_BY_FILE` keyed by basename `count-c1.py`→28, `count-c2.py`→26) is run before any mutant. Good.
- **Timeouts/abnormal exit.** `selftest_run` returns `(124,"timeout")` on `TimeoutExpired`; that is red with no FAIL line, so `unattributed`. Signals give negative rc, also red. Neither can be killed. Verified by reading; not executed.
- **Met gate.** `met` requires pristine_ok, total>0, survivors==0, unattributed==0, no empty/unanchored extras; `main` prints `C2=met` only if `own_ok`, `met`, and `target_split(tail)` (exact `mutants=12 killed=12 survivors=0 unattributed=0 unanchored=0 arms=28,26`) all hold. No false met path found.

### Findings

**F2 (low, instrument; direction safe).** `main()` runs its own `--selftest` and the subject/real/fixture runs without exception handling for `subprocess.TimeoutExpired` (`run()` default timeout 300 s). A timeout there propagates as a traceback with exit 1, not the documented exit 2 setup and without a `C2=` line. Never a pass; violates "exit 2 is setup".

**F3 (medium, attribution residual; not closable by the frozen rule).** The rule is many-to-one per file: a declared arm counts as killing a mutant if it prints `FAIL <arm>` in the mutated copy, whatever else the arm asserts. Nothing in the counter checks that a declared arm is *specific* to its mutant. An arm that fails under every mutation of its file (e.g. a whole-file identity or hash check) would satisfy all labels that share it (`own_ok_red` is shared across the two files and is file-scoped, so that particular case is bounded). Pristine-green cannot catch this because pristine passes every arm. When candidates land, L1 should record, for each mutant, the full FAIL-set and report any declared arm that also fails under another mutant of the same file (over-attribution). This is a report-side check, not a predicate change.

**F4 (low, canary control weak).** The `canary_unattributed` arm feeds a canary whose *pristine* is itself red (`sys.exit(1)` with no FAIL). Its `not met` is therefore satisfied by pristine-red as well as by the unattributed rule; the arm asserts only `unattributed==1 and killed==0`, which is the rule under test, so the arm is valid but not a clean green-pristine/red-mutant canary. The contract's canary control (§3) is met in substance.

**F5 (low, lenient pristine green).** `red()` ignores the bare word `FAIL <label>` and only reads `fail=[1-9]` and rc; `green()` requires `"fail=0" in out`. A pristine whose arm prints `FAIL x` with rc 0 and tally `fail=0` reads green. A mutant with the same shape reads survived (not killed), so the kill side is conservative; the pristine side is lenient only when the subject's own tally lies. Low risk for E01/E02 candidates, which compute the tally from the same arm results.

**F6 (low, anchor location).** `base.count(old)` counts occurrences in string literals and comments as well as code (the r88 matrix hit this: "anchors also appeared inside frozen mutant string literals"). An anchor that appears once but inside a fixture literal would mutate data, not logic, and could be killed by a non-target arm only if that arm reads the literal. Attribution still requires the declared arm, so this is not a false kill, but L1 should confirm each candidate anchor sits in code.

**F7 (low, public path).** The counter never runs the subject from its public path; it runs a copy under `--scratch` (`selftest_run` passes no `--scratch`; mutant copies resolve `__file__` under scratch). Any candidate arm that resolves repo-relative paths via `__file__` would measure a different path than the lane. Current pure arms are unaffected. Before the C2 verdict, L1 should also run the public selftest from a `git clone --shared` at R (`python3 -I <clone>/.ufo/waves/round-88/count-c2.py --selftest`) to confirm the copies match.

**F8 (out of C2 scope, reported for L1).** `round-89/count-c1.py` prints `FX <kind> accepted|refused` from the expectation outcome, not the gate's receipt outcome (`"accepted" if good else "refused"`). Control evidence line 6 reads `FX comment refused problems=-`, while the gate **accepted** the receipt (`problems=-`). The printed label is inverted for the comment/selfprint fixtures. This is the C1 reviewer's domain (Mo89R01C1); noted, not amended (frozen).
