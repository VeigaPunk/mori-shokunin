## Rule backed, verdict

The quote backs these contract §C2 xfs rows:

- `xfs` + any of `usrquota,uquota,quota,grpquota,gquota,prjquota,pquota`, no `noquota` →
  `enabled` / `enforced` / `xfs_quota_option`: the enforced branches print the canonical
  `usrquota`/`grpquota`/`prjquota` only when the corresponding `*_ACCT` **and** `*_ENFD` bits
  are set (parse branches 1547-1552, 1559-1563, 1569-1573 set both together).
- `xfs` + only `*noenforce` keys, no `noquota` → `enabled` / `accounting_only` /
  `xfs_quota_option`: printed exactly when `*_ACCT` is set and `*_ENFD` is clear (238-251;
  parse branches 1553-1558, 1564-1568, 1574-1578).
- `xfs` + `noquota`, no quota key → `disabled` / `n/a` / `xfs_noquota_option`: 253-254 prints
  `noquota` exactly when no quota type has accounting on. In this file's mount path the
  enforced parse branches always set `*_ACCT` together with `*_ENFD` (1547-1552, 1559-1563,
  1569-1573), so kernel-produced text cannot show enforcement without accounting.

**Supports** (observed, kernel-generated text): the enforced-vs-accounting distinction, the
canonical token set, and the disabled meaning of `noquota`. The call site at
`fs/proc_namespace.c:186-187` confirms this text is what reaches mountinfo's super-options
field, and `xfs_super.c:1344` confirms the hook.

**Under-determines** (this file neither states nor refutes):

1. The conflict row (`noquota` together with any quota key → `unknown` /
   `xfs_conflicting_quota_options`). The kernel never emits that combination: `Opt_noquota`
   clears `XFS_ALL_QUOTA_ACCT` and `XFS_ALL_QUOTA_ENFD` (1542-1545), and mount parsing is
   order-dependent, so a conflicting command line resolves last-wins and show_options prints
   only the resolved state. Classifying hand-edited/truncated text is the probe's policy, not
   taught here.
2. The absent row (neither `noquota` nor any quota key → `unknown` /
   `xfs_quota_options_absent`). For a mounted XFS, show_options always emits at least one of
   `noquota`, a `*quota`, or a `*qnoenforce` token. Absence therefore signals non-kernel text
   (truncation/rewrite); "unknown" is a defensible anomaly fallback, but the source prescribes
   no classification for it.
3. Emission of the alias tokens. `quota`, `uquota`, `gquota`, `pquota` and the generic
   `qnoenforce` are accepted at mount time (157-168) but are never printed by 238-254; a real
   mountinfo line contains only the canonical tokens. The contract table's wider key set is
   input-side vocabulary, not observed output. Likewise 238-251 are `if`/`else if` per quota
   type, so a kernel-produced line never carries both an enforced token and a `*noenforce`
   token for the same type; a text with both is synthetic and the table's enforced row would
   win by key presence alone.
4. `qnoenforce` is user-quota, not a type-neutral key: 1553-1557 maps it to
   `XFS_UQUOTA_ACCT` with `XFS_UQUOTA_ENFD` cleared. The table's group listing is correct for
   `accounting_only`, but a per-type mapping would see user quota.
5. Live versus mount-time state. show_options reads `mp->m_qflags` at call time, so the text
   reflects current accounting/enforcement state rather than the original command line
   (observed by reading 238-254). Remount-transition races are outside this file.
6. `CONFIG_XFS_QUOTA=n` builds: quota mount flags are rejected (1636-1639);
   [INFERENCE from 253-254] an ordinary mount then prints `noquota`. The state mapping is
   unaffected, but the mountinfo text does not distinguish build-time absence of quota support
   from runtime disablement.

**Contradicts:** nothing. Every §C2 xfs mapping that this file touches is either directly
supported (rows tied to canonical emitted tokens) or untouched by it (conflict/absence policy,
other filesystems).
