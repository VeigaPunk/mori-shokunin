Located anchors, re-read in the opened files (no claim here is copied from an earlier
note):

- **S087** — `fs/ext4/super.c:1930-1939` maps `Opt_quota`/`Opt_usrquota`/`Opt_grpquota`/
  `Opt_prjquota`/`Opt_noquota` onto `EXT4_MOUNT_QUOTA`, `EXT4_MOUNT_USRQUOTA`,
  `EXT4_MOUNT_GRPQUOTA`, `EXT4_MOUNT_PRJQUOTA`; `:5691-5695` enables quotas at mount
  only `if (ext4_has_feature_quota(sb) && !sb_rdonly(sb))`; `:7250-7270`
  `ext4_enable_quotas` passes `DQUOT_USAGE_ENABLED` for every quota type with a quota
  inode and adds `DQUOT_LIMITS_ENABLED` only for a type whose mount flag was set
  (`quota_mopt[type] ? DQUOT_LIMITS_ENABLED : 0`). Quote (7 words): "Enable usage
  tracking for all quota types." — so the doc's "ignored by the filesystem" wording is
  not the whole mechanism.
- **S088** — `include/linux/quotaops.h:124-163`: `sb_has_quota_usage_enabled`,
  `sb_has_quota_limits_enabled`, `sb_has_quota_suspended`, `sb_has_quota_loaded`
  (returns `sb_has_quota_usage_enabled`), and `sb_has_quota_active` =
  `sb_has_quota_loaded(sb, type) && !sb_has_quota_suspended(sb, type)`. Quote (6 words):
  "return sb_has_quota_loaded(sb, type) && !sb_has_quota_suspended(sb, type);" — active
  accounting is not the limits-enabled bit, so an active accounting token is not proof
  of runtime enforcement.
- **S089** — `fs/quota/dquot.c:2641-2670` `dquot_quota_disable` returns `-EOPNOTSUPP`
  when the request names accounting ("We don't support turning off accounting via
  quotactl"), filters to types whose limits are enabled, and calls
  `dquot_disable(sb, type, DQUOT_LIMITS_ENABLED)`; `:2291-2317` `dquot_disable` clears
  only the requested per-type flag and keeps quota loaded when usage remains enabled.
  Quote (5 words): "ret = dquot_disable(sb, type, DQUOT_LIMITS_ENABLED);"
