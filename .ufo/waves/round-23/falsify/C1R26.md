## 5. Findings (defects that bound R26; none falsifies it)

**M1 — MEDIUM — the frozen fixture field that carries R26's population is misnamed, and the
contract prose reads differently from the operative predicate.**
`round-22/frozen/fixture-builder-v2.py:107` returns
`'expected_policy_hits':[h for h in hits if h['path']=='non-author.txt']` — i.e. the hits removed
by the policy's `non_author_paths_glob`, **not** hits under `must_redact_paths`. R26's text
(`contract.md:43-47`) says "raw hits (expected scanner hits + expected policy hits from the frozen
r22 builder)"; read naturally ("policy hits" = must-redact-path hits) the expected constants would
be 1 (valid) and 5 (forbidden), not the frozen 2 and 4. The frozen predicate (`oracle-rename.py:66-76`)
is operative and yields 2/4, and the builder's own naming is the tie-breaker, so the frozen
requirement is self-consistent — but the requirement *text* does not self-describe its population.
Consequence if the dependency were ever re-derived: R26 goes **red** (tool 4 vs recomputed 5), not
silently green, so this is a readability/robustness defect, not a soundness hole. The bytes are
frozen and hash-pinned for r23; the correction belongs to a future round (rename/pin the field
meaning, or restate R26's population as "all raw hits").

**M2 — MEDIUM — R26 cannot separate "identities" from "hits"; the contract says identities, the
tool counts hits.**
`contract.md:32-33` defines `raw_not_allowlisted` as "raw **identities** not covered by a
non-forbidden allowlist row"; `tools/mori-retention-reconcile.py:235` counts **hits**
(`sum(... for h in hits)`), and the allowlist row identity is `(path,class,line_sha256)` while the
hit identity in the tool is `(path,line,class,line_sha256)`. The frozen fixture cannot expose the
difference: the only duplicated identity is `allowed.txt`'s two byte-identical lines
(`fixture-builder-v2.py:40`), and that identity *is* covered by an allowlist row, so it never enters
the uncovered count (2 and 4 coincide under both readings). Concrete counterexample class (outside
R26's frozen scope, for the next round): a file with two byte-identical uncovered lines and no
allowlist row would yield SUT `raw_not_allowlisted` = 4 but identity semantics = 3; R26 as frozen
would not detect it. Bounded statement: R26 validates the raw-complement value for the frozen arms
only, and the "identities" wording of the contract is not pinned by any frozen predicate.

**L1 — LOW — R26's own evidence row under-describes what it gates.**
`oracle-rename.py:76` applies the forbidden-arm conjunction *after* the row was recorded, via
`data['results'][-1]['pass'] &= …`. The recorded row is
`{'id':'R26','pass':true,'variant':'valid','expected_exit':0,'expected_finding':'RETENTION_RECONCILED'}`
(`evidence/measure4/c1-after-observed.json:results`) — it never names the `forbidden` arm it also
gates, and there is no separate row for it. A reader of the committed artefact sees a single-arm
requirement. The `forbidden` arm *is* actually exercised (its stdout is in the same file:
`raw_not_allowlisted: 4`), so this is evidence-fidelity, not coverage loss.

**L2 — LOW — the oracle's independent count and the SUT read different revisions of the fixture
by construction.
The oracle reads the policy/allowlist at the fixture's `HEAD` (the retained-receipt commit,
`oracle-rename.py:69-71`), while the SUT scans hits at `measured` (`:207`) and reads the
policy/allowlist at the `--rev` commit (`:165-166`, equality with the measured copy checked at
`:177`). For the frozen fixture these
bytes are identical (only `receipt.json` is added in the second commit), so the comparison is
apples-to-apples. A future builder variant that changed the policy between the two commits would
either trip the SUT's own `policy_changed` setup error (loud red) or, if only the allowlist moved,
compare the SUT's coverage against a different row set. Robustness note only; the fixture bytes
are frozen.

**L3 — LOW — R25's alias detection is top-level only.**
`oracle-rename.py:82` computes `misleading_alias_runs=sum('raw_unallowlisted' in o for o in parsed)`
— a top-level key test. A nested occurrence (e.g. inside `raw_hits` entries) would not be counted,
while `contract.md:30` says the key is removed from *every* output. For this cutover the hole is
closed by the byte guard (the alias producer fragment is absent and no other key may change), and
the tool's output has no nested structures carrying that name. Independently confirmed; flagged
because it is the same limitation the build wave recorded.

  (2 / 4). It is green **before and after** — it is an *unchanged semantic requirement*, not part of
  the cutover, and it is the only original-26 requirement that constrains that field's value.

  `scanner_unallowlisted` with the *same* `len(unallowed)` value, `tools/mori-retention-reconcile.py`
  at `1bfe708:231-232`), so the 25/26 → 26/26 movement is attributable to R25 alone.

  `selftest`, `source_byte_guard`, `source_guard_mutants`) are unchanged-semantics instruments; they
  are *not* evidence for the raw-complement semantics beyond the one fixture pair (R26) and the
