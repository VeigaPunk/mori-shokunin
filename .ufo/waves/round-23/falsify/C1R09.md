## 7. Axis G — discriminating power, and the bounded counterexample

### 7.1 What R09 kills (proved from the arm's structure)

Given that every counter is unchanged and only the `class` value differs, an implementation that omits `class` from the comparison identity returns exit 0 on the `class` arm ⇒ R09 red. Concretely, a comparator whose `hit_key` were `(path,line,line_sha256)` would see `claimed['hits'] == Counter(hit_key(h) for h in actual)` (same paths/lines/shas) and `claimed['allowlisted_hits']` likewise, and would then also agree on `metric`, `routed`, `non_author`, `finding_id` and `exit_code` (all recomputed from the tree, all equal to the receipt's unmutated values) ⇒ `differences == []` ⇒ exit 0 `RETENTION_RECONCILED`. R09 therefore **does** kill count-only, per-path-counter and class-blind comparators.

### 7.2 The bounded counterexample (against R09 as a *frozen requirement*)

Two independent facts combine into a concrete, non-blanket gap.

**(a) The frozen fixture cannot express a class *permutation*.** The policy declares one class id (`R22`). Every hit in the fixture carries class `R22`, so the only class mutation expressible is `R22 → R23` (an id outside the policy). The r22 critic's M9c arm — "swap classes R5↔R6 between two lines, in both `hits` and `unallowlisted_hits`", the arm that "only full 4-tuple identity detects" (`round-22/build/AttackR09.md`) — is **unrepresentable** in this fixture, because there is no second class to swap in. The frozen 26 therefore contains no arm that distinguishes 4-tuple identity from per-field comparison.

**(b) R09's predicate does not pin the difference content.** `record()` asserts exit code, `finding_id` and stderr — not `differences`, not any counter. Hence a comparator that compares receipt hits as **per-field multisets** (multiset of paths, of lines, of classes, of shas — separately) satisfies R09: the class multiset changes (`{R22×5}` → `{R23, R22×4}`), so it reports `MISMATCH`/exit 1 exactly as the frozen predicate demands. Such a comparator nevertheless violates the governing r22 contract text (`round-22/contract.md` line 13, "Hit identity=(path,line,class,line_sha256)") and accepts a receipt whose two hits' classes are swapped (M9c) as `RETENTION_RECONCILED`, exit 0.

**Concrete counterexample statement.** Take the frozen `valid` fixture and emit a receipt whose `hits` and `allowlisted_hits` have two entries' `class` values exchanged (a class-permutation receipt). Under a per-field-projection comparator this receipt is *reconciled* (exit 0, `RETENTION_RECONCILED`); under the contract-mandated 4-tuple identity it is a mismatch. The frozen R09 arm cannot tell these two comparators apart, because in the frozen fixture the permutation is inexpressible and the predicate never inspects `differences`.

**Scope of the claim.** This is a *predicate-granularity* limit of the frozen requirement, inherited unchanged from r22 (the r22 critic raised it; the r23 contract froze R01–R24 "byte-for-byte" and did not add the M9c arm). It is **not** a defect in the production tool: at `f3dc07c0` the tool's `hit_key` is the 4-tuple, so the class-permutation receipt produces `differences == ['hits']` and exit 1 — the tool is correct where the frozen arm is merely imprecise. **R09's truth value at `f3dc07c0` is therefore true**, and the counterexample is against R09's *sufficiency as evidence*, not against the implementation.

*(Option for the parent/L1, not executed and not applied here: a **supplementary** two-class arm, labelled and reported outside the frozen original-26 denominator, could certify the 4-tuple identity. This seat made no change to any frozen byte, fixture, expectation or oracle.)*

### 7.3 A second, inherited boundary: unknown receipt class ids

R09's mutated id `R23` is **not** in the policy's class set. The tool's `normalize_hits` (lines 124–131) requires only `isinstance(hit['class'],str) and hit['class']` — no membership check against the policy's class ids — so an unknown class id is answered `MISMATCH`/exit 1, not `SETUP`/exit 2. The r22 critic recommended exit 2 for this case ("N2 … class changed to an id outside the frozen policy … Recommend exit 2 `RETENTION_RECONCILIATION_SETUP`", `AttackR09.md`) and flagged the choice as a semantic ambiguity the contract had not frozen. No requirement in the frozen 26 pins it. Consequence: **R09's green is contingent on the absence of receipt class-id validation**; an implementation that later adopted the critic's N2 recommendation would turn R09 red with exit 2 `RETENTION_RECONCILIATION_SETUP`. This is unchanged by C1 (r22 froze the same arm and the same expectation) and is recorded as a latent coupling, not a current failure.
