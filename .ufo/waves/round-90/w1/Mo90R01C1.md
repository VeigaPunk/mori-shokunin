Every command below: `executed=true` (rc 0, `RECORD_SWEEP pending=0 pinned=0 carriers=1 bindings=3

2. `(exit 1)|| python3 -I tools/mori-record-sweep.py --root . --pins .ufo/waves/round-82/record-pins.json`

5. `(exit 0);  python3 …` (any glued `)`+separator spelling; the four above are the graded variants)

Root cause (pinned to sha 79350315…, `invocations_visited`): shlex glues the close paren to the
following separator (`);`, `)||`, `)&`). The dispatch
`elif set(token) <= CONTROL and token not in ("(", ")")` sends such a composite token to the
separator branch, so `)` never pops the `(` group pushed on the stack; the in-subshell `exit`
flush sets `terminated=True`, and `live = live and not terminated` kills the rest of the *parent*
list — although a subshell exit cannot terminate its parent, and the sweep runs. Control: the
spaced spelling `(exit 0) ; python3 …` binds correctly, isolating the defect to composite `)`
tokens. Fix direction: process a group-close inside any composite control token before applying
the separator's liveness rule.
