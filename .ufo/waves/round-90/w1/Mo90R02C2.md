## Findings by severity

### F1 HIGH — `killed` attribution is forgeable by a label-accurate canary (probe 6, beyond the enumerated five)
A subject that (a) is green at `pass=29 fail=0` pristine, (b) trips on any edit via a self-seal
hash, and (c) maps **each declared anchor-edit to exactly its own declared label** (mutation-text
match, no anchor duplication) reads `killed` on all four count-c1.py mutants. The frozen clause
`killed ⟺ red ∧ failset(out)=={arm}` cannot distinguish this from a sensitive arm; the
blanket-canary (`isolated`) and `unattributed` clauses do not fire — the label set is exactly
`{arm}`. Command: substitution commit `be8a2ce4…` (= `d1c84889…` + count-c1.py→forger, verified
`git diff --stat` one path only), then the counter. Observed lines:

```

MUTANT count-c1.py C1-green-drop-fail killed rc=1 arm=green_mixed_fail

C2=unmet mutants=15 killed=13 survivors=2 unattributed=0 unanchored=0 isolated=0 literal_anchors=0 arms=29,26 detector=green rev=be8a2ce4de4a
```

The claim stays unmet here only because the real c2 side still has 26 arms and B4/B6 survive;
the c1-side kill credits are fully forged. The forger's c1 reading is **byte-identical** to the
honest candidate's (p7 below) — the counter cannot tell them apart. [INFERENCE] The same
pattern extends to count-c2.py's 11 anchors; combined with a green 27-arm c2 subject, the frozen
target string `C2=met … killed=15 …` would be reachable while both subjects assert nothing.
Recommendation for the L1 (new arm, cheap): a negative control — apply a benign noop edit
(e.g. append `# noop`) to a pristine synthetic subject and require the detector to stay green; a
self-seal canary fails that control, a per-edit forger fails it under any non-declared edit.
