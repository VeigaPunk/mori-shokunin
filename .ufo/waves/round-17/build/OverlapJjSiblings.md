# Mori round 17 — jj overlap conventions

**Scope:** one bounded C2 consistency proposal; this report does not judge or integrate. Sources read locally on 2026-10-20: the round-17 contract and the named hyaku `JjAudit*.md` reports. No commands, tests, or probes were run by this seat; quoted probe outcomes below are those recorded in the cited audit reports. No tools were installed or updated.

## Axes

- **C2 operability (7):** improve branch-anchored census behavior and explicit detection of jj-colocation drift.
- **C1 coverage (6):** leave the independent seat-terminal-status tool and its coverage unchanged. The contract says C1 is standalone and C2 changes only the census (`mori-shokunin/.ufo/waves/round-17/contract.md:9-22`).

## Evidence and consistency notes

- Mori's audit directly measured the relevant divergence: after a jj commit, `git rev-parse HEAD` was `d19d559…` while `git rev-parse master` was `611dfb5…`; its `git log` output likewise distinguished lane-authored HEAD from the branch's ambient-author commit (`/home/vgpnk/Projects/shokunin/.ufo/waves/hyaku/jj-w1/reports/JjAuditMori.md:62-77`). Its author probe showed `git config user.name mori-shokunin` alone yielded ambient author `<operator ambient git identity withheld>` with lane committer; the helper-shaped `metaedit --update-author` path yielded lane author and committer (`JjAuditMori.md:79-98`). Mori recommends a census-local resolver and querying `refs/heads/$branch`, plus separate mismatch findings (`JjAuditMori.md:251-271,283-291`).
- The round-17 contract is the naming and resolver authority for this change: resolve `symbolic-ref -q HEAD` → `refs/remotes/origin/HEAD` → unique local `master`/`main`; use `refs/heads/<branch>` for closure and progress; name the findings exactly `HEAD_BRANCH_MISMATCH` and `LANE_AUTHOR_MISMATCH`, with the stated predicates (`mori-shokunin/.ufo/waves/round-17/contract.md:80-90`).
- A sibling audit corroborates branch anchoring and reports a related but differently named finding: Kumitate recommends `HEAD_NOT_ON_BRANCH` separately from `UNPUSHED`, because branch/upstream counts do not reveal an unbookmarked HEAD commit (`JjAuditKumitate.md:71-87,196-201`). **Naming conflict:** do not introduce that alias into Mori's interface; use the contract's `HEAD_BRANCH_MISMATCH` for its specified `merge-base --is-ancestor HEAD refs/heads/$branch` failure. Keep it distinct from progress/upstream findings.
- Resolver edge case: InlineSh recorded `symbolic-ref -q --short HEAD` returning `jj/root` while the only local branch was `refs/heads/master`; its state showed `branch=jj/root local=- remote=- ahead=0` (`JjAuditInlineSh.md:217-228`). That audit recommends accepting symbolic HEAD only if `refs/heads/<b>` exists, otherwise falling through to `origin/HEAD`/`master`/`main` (`JjAuditInlineSh.md:371-376`). Kumitate's ladder also has a final “first local branch” fallback (`JjAuditKumitate.md:198-199`), but Mori's contract is narrower: use a unique `master`/`main`, not an arbitrary local branch.
- **Authorship boundary/contradiction:** the Mori contract's `LANE_AUTHOR_MISMATCH` is deliberately one-directional: branch commit committer equals lane identity, author differs (`contract.md:88-90`). ClosurePrompt reports rejected-push rebase can instead retain a lane/protocol author while rewriting the committer to the lane config or even ambient identity; it concludes an author-only conformance check misses that case (`JjAuditClosurePrompt.md:22-63`). Thus `LANE_AUTHOR_MISMATCH` is not a complete “commit identity is correct” assertion and should not be described as one. Preserve its contract predicate; broader committer-drift detection would be a separate interface/claim, not folded into this finding.

## Proposed move

Have C2 resolve the branch once into a **validated local branch ref** and reuse that value for every branch-sensitive census query. Accept the symbolic-HEAD candidate only when the corresponding `refs/heads/<branch>` exists; otherwise continue through the contract's `refs/remotes/origin/HEAD` and unique `master`/`main` fallback. Do not use bare `HEAD`, `@{u}`, `--abbrev-ref HEAD`, or an arbitrary first-local-branch fallback as the branch identity. Query `refs/heads/$branch` for report closure, the post-launch log, and progress; compare HEAD to that same ref for `HEAD_BRANCH_MISMATCH`. Emit the two contract IDs verbatim, preserving the defined author-check predicate.

This is a narrow improvement to **C2 operability**: it prevents an invalid symbolic ref such as `refs/jj/root` from being mistaken for a lane branch, while keeping the census's branch decision consistent across all four probes. It does not alter C1 or the existing A/B/C grading semantics.

## Risks and verification

- If no unique local branch can be selected, silently choosing an arbitrary ref would recreate the ambiguity; the resolver should fail closed / report unresolved rather than grade against a guessed branch. The contract does not specify the exact unresolved output, so that output detail remains for the integration owner to choose.
- Do not present `LANE_AUTHOR_MISMATCH` as detecting the ClosurePrompt committer-drift case: by contract it only flags lane-committer/non-lane-author commits. The cited helper recovery behavior is a separate, observed identity failure (`JjAuditClosurePrompt.md:22-63`).
- The audit-reported detached-HEAD and author cases are sandbox observations, not fresh runs in this seat. No verification was performed here. The contract's C2 regression gate (`mori-shokunin/.ufo/waves/round-17/contract.md:91-94`) should verify: (1) a stale/detached HEAD is compared against the branch and gets exactly `HEAD_BRANCH_MISMATCH`; (2) `refs/jj/root` does not win over an extant branch; (3) unique `master`/`main` fallback selection; (4) the specified lane-committer/other-author case produces `LANE_AUTHOR_MISMATCH`, with a normal lane-authored commit as a negative control; (5) the branch-relative change leaves A/B/C grades unchanged. A recovery-rebase committer mismatch should be recorded as the known coverage boundary, not silently treated as covered.
