## Findings

- **MED — census blind spots visible in S521: handled failures that leave no memory-failure evidence at all.**
  (1) The arch hook at 2405–2407: when `pfn_to_online_page` fails, `memory_failure` calls `arch_memory_failure`
  and returns success (no recovery line, no counters, no tracepoint) if it returns 0. On x86 with CONFIG_X86_SGX
  that override is real at v7.3 (`arch/x86/kernel/cpu/sgx/main.c` 684–740, fetched from cgit): it marks the EPC
  page poisoned and can `force_sig(SIGBUS)` to the consuming task, then returns 0 — a handled failure, possibly
  with a SIGBUS kill, and none of the four evidence surfaces the entry names. (2) `mf_dax_kill_procs`
  (1832–1858, the FS-dax `.notify_failure` entry in the same file): `SetPageHWPoison` + `collect_procs_fsdax` +
  `unmap_and_kill` (SIGBUS, MF_MUST_KILL) with no `action_result` call — again no line, counters or tracepoint.
  Consequence for the entry's decision-table row "no line and all counters 0 → no memory failure handled since
  boot": on a kernel with SGX or FS-dax notify in play, a handled failure (possibly with a kill) can leave every
  structured surface at zero. This is entry prose/decision-table material for the L1 to correct (data, not
  counter — the counters are frozen) and a routed item for round 55. It does not change any vote: the claim rows
  are scoped to the recovery step, which these paths never enter.
- **LOW — row 7's "ends in" under the panic switch.** With `panic_on_unrecoverable_memory_failure` set to 1 and a
  reserved kernel page reported Ignored, a panic message ("Memory failure: %#lx: unrecoverable page", 1295)
  follows the recovery line. The recovery line remains the one KERN_ERR line naming page type and outcome, and
  the panic is a separate decision-table row in the entry, so the claim holds as worded; noted for completeness.
- **LOW — row 10's per-node update has one more early-out the claim does not mention.** `update_per_node_mf_stats`
  returns without advancing on an invalid node id (WARN_ONCE, 1240–1244). Whether any page reaching
  `action_result` can have an invalid nid is UNVERIFIED from this copy; no vote impact (the claim's exclusions are
  by page type, and the verified first half is unaffected).
