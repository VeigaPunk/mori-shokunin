### row 1 — 4aab78fbca9c — include/linux/percpu_counter.h, v7.3 line 121 (v7.2 121)
Claim: the mode-2 read takes only the global count and returns zero for a negative value, never summing
the per-CPU deltas.
v7.3: `percpu_counter_read_positive` (118–126) returns `READ_ONCE(fbc->count)` clamped at 0; it never
touches `fbc->counters`. The summing path is separate: `percpu_counter_sum_positive` wraps
`__percpu_counter_sum` (97–101, declaration at 58). File byte-identical between the tags.
Verdict: holds.
Careless-reader note: `percpu_counter_read` (108–111) is the raw global read and may go negative — the
clamp lives only in the `_positive` variant; on !SMP (244–248) the sum/read distinction collapses.

### row 2 — c8fb3a4fb56f — lib/percpu_counter.c, v7.3 line 100 (v7.2 100)

`this_cpu_try_cmpxchg` (112); fold into `fbc->count` under `raw_spin_lock_irqsave` exactly when

Verdict: holds.
Careless-reader note: the quoted line sits in the CONFIG_HAVE_CMPXCHG_LOCAL variant; a second, generic
