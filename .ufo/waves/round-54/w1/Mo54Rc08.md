## What a careless reader might miss (v7.2 -> v7.3 diff, per row)

- Rows 17/19/20/23 (`mem_cgroup_print_oom_meminfo`): the function body is unchanged, but
  `mem_cgroup_css_alloc` (v7.3 ~4279-4292) moved `WRITE_ONCE(swappiness,…)` and
  `memory.track_failcnt` inside `#ifdef CONFIG_MEMCG_V1` and **newly enables**
  `memcg->memsw.track_failcnt` and `memcg->tcpmem.track_failcnt` for v1. The v1
  `memory+swap:`/`kmem:` failcnt fields this function prints (v7.3:1860-1865) were
  effectively always 0 in v7.2; at v7.3 they can be non-zero. The v2 failcnt claims
  themselves are unaffected — the read site is unchanged.
- Row 21 (`mem_cgroup_print_oom_group`): v7.3 adds `WRITE_ONCE(memcg->oom_group, false)`
  plus zswap init in the css-init path (v7.3 ~4424-4429): a recreated cgroup no longer
  inherits `oom.group`. Also `try_charge_memcg` was renamed to `try_charge` (v7.3:3161)
  and `try_charge` gained an early `tsk_is_oom_victim` bail-out (v7.3:2701-2710) so OOM
  victims' charges fail fast instead of queueing — the kill path still emits the same
  lines, but the charge path around it changed shape.
- Rows 18/22 (`mem_cgroup_print_oom_context`): no change in the function or its caller;
  the +45 line shift comes entirely from earlier hunks (new `memcg_uncharge_kmem`
  helper, `lruvec_page_state_monotonic`, enum items `NR_VMSCAN_WRITE`,
  `PGROTATE_ANON/FILE`).
- Row 16 (`memory_stat_show`): the `memory_stats` key table (v7.3:1591-1641) is
  unchanged despite the new `NR_VMSCAN_WRITE`/`PGROTATE_*` enum items — they are not
  `memory.stat` keys. `memcg_stats_index` arithmetic and `MEMCG_VMSTAT_SIZE` (v7.3:448)
  changed around them without renaming printed keys.
- File-wide: upstream v7.2 `mm/memcontrol.c` line 2042 itself contains the stray text
  `e patches/memcg-uint16_t-for-nr_bytes-in-obj_stock_pcp.patch` before
  `* sub-page remainder. Such archs are not cacheline optimization target.` — a commit
  artifact present in the v7.2 release blob (verified: the committed copy's sha256
  equals the fresh cgit fetch), cleaned at v7.3:2087 (`…optimization targets.`). It is
  inside a comment and shifts no line numbering, but a reader grepping diffs could
  misread it as copy corruption.
