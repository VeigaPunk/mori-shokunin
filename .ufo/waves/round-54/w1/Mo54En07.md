- context: whole copy read (182 lines). The overview comment (lines 16–25) sets the frame: the handler "Handles pages reported by the hardware as being corrupted" (16–17) and "focusses on pages detected as corrupted in the background" (20); when the current CPU consumes corruption, "the currently running process can just be killed directly instead" (21–22). The "Failure recovery modes" section (54–72) defines early kill (62–67): "Send SIGBUS to the application as soon as the error is detected" (64), "This allows applications who can process memory errors in a gentle way (e.g. drop affected object)" (65–66); late kill (69–72) is defined by the touch trigger ("Send SIGBUS when the application runs into the corrupted page", 70).
- judgment: "the background check finds the error" = "detected as corrupted in the background" (20) plus "as soon as the error is detected" (64): the signal is sent at detection, and detection is in the background, not caused by a process touch. "before any process touches the page again" is the mode's own contrast — late kill is defined by the touch trigger (70) and a consuming process is killed directly (21–22) — so the early-kill signal is not waiting for a touch. No word says more than the copy.
