## Evidence notes

- The baseline data revision `78295c764093ff1f6cee08d7246679900bde7265` scored `C1=unmet … voted=0 failed=votes`, exit 1, agreeing with `evidence/c1-at-data.txt`.
- The fabricated settlement plus copied reports is the cheapest attack set: one committed results file and two committed report files are enough to turn the authentic data commit into `C1=met` without any recheck. This is the strongest counterexample to voter binding as an identity guarantee.
- No host reads, source re-fetches, tool installations, or fleet-repository mutations were performed. Fixture changes were confined to the shared clone.

## Findings

- **HIGH** — `.ufo/waves/round-54/count-c1.py:243-263`: results-name plus expected filename lets one writer fabricate settlement and two distinct voter identities; C1 can become met without an honest recheck.
- **HIGH** — `.ufo/waves/round-54/count-c1.py:322-348`: a disposition opposite the counter-derived `held` status passes when votes match the disposition.
- **MED** — `.ufo/waves/round-54/count-c1.py:153-161,330-332`: line verification accepts any occurrence of duplicated quote text; the attempted duplicate is semantically the same warning, so an unrelated-context bypass is not proven.
- **MED** — `.ufo/waves/round-54/count-c1.py:255-267`: fenced dissent and indented code-block votes can diverge from what a human considers report prose/votes; parser accepts only tokenized unfenced lines (but leading indentation remains accepted).
