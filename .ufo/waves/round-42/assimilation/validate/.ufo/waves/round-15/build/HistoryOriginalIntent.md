# HistoryOriginalIntent — R14 mixed-invalid control and R15 positive fallback

Seat: `MoriR15.HistoryOriginalIntent` (report-only, leaf). Axis: **coverage**. The report uses committed R14 source, harness, and receipts; it does not modify those artifacts or claim a gate run.

## Finding

R14 deliberately kept each raw journal class all-or-nothing. Its retained mixed-invalid control demonstrates that a valid positive kernel OOM record is discarded for aggregate purposes when an adjacent record in the same class has an array-valued `MESSAGE_ID`: the class reports `unavailable:record-invalid`, no OOM finding is emitted, and the run remains CLEAN. The unavailable value was intentional disclosure rather than a zero; R14 explicitly accepted the resulting alarm-suppression residual.

The smallest compatible R15 change is therefore **not** to weaken or partially repair aggregate parsing/counting. Keep every existing raw aggregate and split count unavailable when its class is invalid. Independently derive only the new per-scope positive evidence tokens from the same captured successful, stderr-free, valid JSON stream. Count only object records with scalar `MESSAGE_ID` equal to that path's required id and scalar `_BOOT_ID` equal to the expected current boot; apply the exact event predicate only after those gates. Invalid, nonmatching, and foreign-boot records are excluded from positive evidence, not treated as zero-valued raw totals. Capture or JSON-parser failure leaves positive fields unavailable. No second journal query is needed or permitted by this contract.

Across scopes, any validated positive kernel OOM notice or unit-result OOM record produces **one** `OOM_KILL_JOURNAL crit` alarm, while its separate per-scope evidence remains unsummed. In user scope, any independently valid unit `signal` result or process SIGKILL record produces `KILL_SIGNAL_JOURNAL warn`; system generic unit-signal results remain informational. This keeps the R14 one-finding/roll contract without allowing one invalid neighbor to erase a valid positive.

The source note `:9-16, 48-75` also distinguishes notice records from victims and disclaims unique-victim cardinality.

## Compatible R15 boundary

- Preserve the all-or-nothing status of each existing raw class and all its derived aggregate/split counts whenever any record makes that class invalid. Do not convert unavailable to zero, count invalid records, or claim that R15 repaired the aggregate class.
- Add only `positive_kernel_oom`, `positive_unit_oom`, `positive_unit_signal`, and `positive_process_sigkill` as per-scope validated-positive evidence. For the latter three, require respectively: unit-result record plus scalar string `UNIT_RESULT` exactly `oom-kill` or `signal`; process-exit record plus exact `EXIT_CODE=killed` and scalar status 9. Require matching scalar id and current scalar boot id for every counted record.
- Compute positives from the already captured JSON bytes after successful capture (rc 0, no stderr) and successful JSON parsing. A parsed stream may contain records excluded from positive evidence; it still leaves the raw class unavailable under the existing whole-class rule. If capture or parsing fails, positive fields are unavailable too. Do not add a query.
- Treat evidence as scoped record/notice counts only. Do not claim complete event coverage, authenticated `MESSAGE_ID`/subject values, unique victims, fleet causation, or arbitrary malformed-JSON recovery. `UNIT_RESULT=signal` is not signal 9; system unit-signal findings remain informational.
