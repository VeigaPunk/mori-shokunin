## 5. Findings and flags

**F1 — the manual's EXIT STATUS table is not the set of codes earlyoom 1.9.0 actually returns.**
The table (MANPAGE.md:222-250) lists `2: Switch conflict.`, `7: Could not open /proc/sysrq-trigger`
and `105: Could not convert number when parse the contents of /proc/meminfo`. An exhaustive search
of the v1.9.0 tree (`grep -rn "fatal(" .` over the extracted tag) finds **no** `fatal(2)`,
`fatal(7)` or `fatal(105)` call site, and no `sysrq` or "switch conflict" string in any source
file — while the code **does** emit `6` ("could not compile regexp", `main.c:377`, `:384`,
`:391`), a code the table does not list. The codes the code emits at v1.9.0 are
`0,1,4,5,6,13,14,15,16,102,103,104`. Consequence: this row must not be cited as an enumeration of
earlyoom's real exit codes; it is the manual's own table only.

**F2 — the manual's threshold wording is looser than the code, and the C2 grammar must follow the
code.** The `-m` section says SIGTERM happens once both values are "below" their PERCENT settings
and SIGKILL once both are "below" KILL_PERCENT (MANPAGE.md:41-45), while the same file says "at or
below" for `-s` (57), `-M` (77) and `-S` (84). The v1.9.0 code compares with `<=`
(`main.c:500-503`), which is also what the printed line says (`mem avail <= 10.00%`). The contract's
C2 grammar quotes the code lines (`main.c:414`, `:416`), so the wording slip in the manual does not
contradict the contract — but the manual must not be quoted for "below" semantics.

**F3 — contradiction risk against contract C2 verdict rule 1 (`--dryrun`).** The manual documents
`--dryrun` as "dry run (do not kill any processes)" (MANPAGE.md:205-206). In the v1.9.0 code the
`sending SIGTERM to process …` / `sending SIGKILL to process …` line is emitted **before** the
dry-run short-circuit: `kill.c:627` prints it, and only then `kill_wait()` returns early at
`kill.c:271-273` with `dryrun, not actually sending any signal`. So a `sending SIG…to process` line
does **not** prove that a process was killed when `--dryrun` is in effect. Contract C2 rule 1
(`KILLER_ACTED`, exit 1) has no dry-run carve-out, although the contract's output schema does carry
a `dryrun` field. Flagging this for the canonical judge verbatim: the rule as written can report
`KILLER_ACTED` for a dry-run earlyoom that killed nothing; the manual's own text ("do not kill any
processes") is the primary-source basis for the caveat. The host is **not** in dry-run mode
(the journal's first line is `earlyoom 1.9.0` with no `dryrun mode enabled` line), so this does not
affect the host capture — it affects the tool's rule set.

**F4 — the periodic memory report line shares vocabulary with the threshold line.** The `-r`
default is 1.0 s and its report format is `mem avail: … MiB (…), swap free: … MiB (…)`
(MANPAGE.md:100-102), which contains the same words "mem avail" and "swap free" as the threshold
line. The contract's C2 grammar is prefix-anchored ("matched after stripping leading whitespace,
prefix-anchored"), so the two cannot be confused; a substring matcher would conflate them. The
host journal shows the report lines are frequent (6 of 13 messages in the current boot), so the
tool will see them.

**F5 — no contradiction with the contract's grammar citations.** Independently re-checked against
the tag bytes: `main.c:161` is the `earlyoom ` version line; `main.c:414` and `main.c:416` are the
two threshold lines; `main.c:519`/`main.c:523` are the SIGKILL/SIGTERM low-memory warnings;
`main.c:295` is the dry-run line; `kill.c:318` is the escalation line; `kill.c:627` is the
`sending %s to process …` line; `kill.c:654` is the `kill failed: ` line. The upstream `main.c`
sha256 `08656b0bc90c85f23738661456b25c97af908bc5e2cfea78e0a69697b5f9d0e4` equals the L1's local
copy, and the upstream `kill.c` sha256
`b32e0fad65e298235102f98aff37e02c94400b544d454cb57192ae697b100bf3` matches it too. The contract's
host-shaped thresholds 10.00/10.00/5.00/5.00 equal the manual's documented defaults (10 %, kill at
PERCENT/2), so the contract and this row agree.

**F6 — this row is not the source for the version-line grammar.** The manual carries no version
statement; the `earlyoom <version>` first line comes only from `main.c:161`. The manual can support
the *version string* fact ("earlyoom 1.9.0", observed on this host) but not the line grammar.

**F7 — privacy exposure the C2 tool must respect.** The manual documents that `-N`/`-P` child
scripts receive `EARLYOOM_NAME`, `EARLYOOM_CMDLINE` and `EARLYOOM_UID` (MANPAGE.md:127-141), and the
`sending … to process` runtime line carries the same three fields. The contract's C2 privacy rule
(the tool never prints `MESSAGE` text, process names, command lines, uids, or the `--avoid`/
`--prefer` expressions) is consistent with this; this row supports that rule with the upstream text.
