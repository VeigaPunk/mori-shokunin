## Counterexample and evidence

The drift token is polarity-sensitive. The r10 baseline contains both `WATCHDOG_STALE` and `WATCHDOG_ABSENT` (`corpus/evidence/baseline-r10-20261015T2231Z.json:24-25`). The entering drift contains `-FINDING:WATCHDOG_STALE` (`.ufo/waves/round-20/evidence/c1-drift-entering.json:48`), i.e. the stale finding disappeared relative to that baseline. The pre-pin list omits that negative token; the L1’s receipt records 50 entering tokens versus 49 pre-pin tokens and says STALE fired again (`corpus/knowledge/drift-repin-r20.md:54-56`). Thus the finding disappeared after a launch wrote the log and returned after the log aged; the daemon’s last recorded tick remained 2026-10-15 (`.ufo/watchdog.log:402-403,582-585`; `corpus/knowledge/drift-repin-r20.md:35-42`).

The check reads `watchdog.log` mtime and emits STALE only when its age exceeds 900 seconds (`tools/mori-census.sh:733-736`). The inline driver appends launch lines to that log (`scripts/hyaku/inline.sh:103`; `.ufo/watchdog.log:584-585`). This is a real heartbeat-provenance blind spot: an unrelated writer can suppress the stale-log signal while no watchdog tick occurs. However, `WATCHDOG_ABSENT` still fires (`corpus/evidence/drift-classification-r20.json:201-205`; also `tools/mori-census.sh:829-830`), so this evidence does not show that the census reported the daemon healthy or hid process absence.

The frozen contract names the four classes and says a `census-regression` blocks the re-pin, but does not define when a changed observation is `live-state` versus a regression (`.ufo/waves/round-20/contract.md:22-30`). The later knowledge document supplies a cause-based rule—unchanged census code plus changed host/fleet state is `live-state`; unintended behavior change is `census-regression` (`corpus/knowledge/drift-repin-r20.md:22-26`). On that interpretation, this token is `live-state`: the mtime input changed and the unchanged age predicate responded accordingly. H2 is nevertheless valid as a design-risk objection if the intended measure is daemon-heartbeat freshness rather than log-mtime freshness.

## Impacted axes and smallest safe correction

Freshness is the selected axis (score 5; `.ufo/waves/round-20/contract.md:4-10`). `census-regression` blocks the pin, so that choice defers the freshness gain and preserves the old baseline. `live-state` permits the pin and advances freshness; it would risk calibration only if the changed log mtime were presented as proof of watchdog health. The register’s `blind_spot`, the still-present `WATCHDOG_ABSENT`, and the explicit rule that post-pin `none` means “unchanged since pin,” not “healthy,” disclose that limitation (`corpus/evidence/drift-classification-r20.json:201-205`; `corpus/knowledge/drift-repin-r20.md:68-72`). No independent axis harm is established if those caveats remain attached.

Smallest safe correction: retain `live-state` for this token only under the cause-based rule, retain its `blind_spot`, and state explicitly that it classifies log-mtime drift—not daemon liveness. Freeze the class boundary and intended watchdog signal in the next contract; if daemon-heartbeat freshness is the requirement, use a daemon-only heartbeat/provenance check and classify this false-clean as `census-regression` until that signal is reliable. Do not change the frozen round-20 files on this review.
