## What the commit actually adds (from the opened diff)

- `include/linux/psi_types.h`: new resource `PSI_IRQ` and new state `PSI_IRQ_FULL`, both
  guarded by `#ifdef CONFIG_IRQ_TIME_ACCOUNTING`; `NR_PSI_RESOURCES` / `NR_PSI_STATES` become
  computed instead of fixed.
- `kernel/sched/psi.c`: new `psi_account_irqtime()` which adds the IRQ/softirq delta to
  `groupc->times[PSI_IRQ_FULL]` for the running task's cgroup chain; new `psi_irq_show` /
  `psi_irq_open` / `psi_irq_write` and `psi_irq_proc_ops`; `psi_proc_init()` adds
  `proc_create("pressure/irq", 0666, NULL, &psi_irq_proc_ops)` inside
  `#ifdef CONFIG_IRQ_TIME_ACCOUNTING`.
- `kernel/sched/psi.c` `psi_show()`: `only_full = res == PSI_IRQ;` and the emission loop
  becomes `for (full = 0; full < 2 - only_full; full++)` with the label
  `full || only_full ? "full" : "some"` — i.e. for the irq resource **only the `full` line is
  ever printed; there is no `some` line**.
- `kernel/sched/psi.c` `psi_trigger_create()`: `if (res == PSI_IRQ && --state != PSI_IRQ_FULL)
  return ERR_PTR(-EINVAL);` — an irq trigger may only be created on `full`.
- `kernel/cgroup/cgroup.c`: new `irq.pressure` cgroup file (read-write nested-keyed file)
  plus `cgroup_irq_pressure_show` / `_write`.
- `kernel/sched/core.c`: `update_rq_clock_task()` calls `psi_account_irqtime(rq->curr, irq_delta)`.
- `Documentation/admin-guide/cgroup-v2.rst`: new `irq.pressure` entry ("Shows pressure stall
  information for IRQ/SOFTIRQ.").
- `kernel/sched/stats.h`: declaration of `psi_account_irqtime()`.

## Rule backed for claim C2 (contract text, not lane policy)

The contract's C2 grammar and state rules are now backed by an upstream primary source:

- "`irq` needs `full` only, and its missing `some` is expected (`some: null`), never malformed."
  → upstream: `psi_show()` prints only the `full` line for `PSI_IRQ` (`only_full`), so a
  kernel-produced `/proc/pressure/irq` never carries a `some` line and the absence is by
  design, not a malformed file.
- "Open/read errors: ENOENT → `absent`" → upstream: `/proc/pressure/irq` is created only under
  `#ifdef CONFIG_IRQ_TIME_ACCOUNTING` and only when PSI is enabled, so on a kernel without
  that option the file simply does not exist; an absent irq file is a build-configuration
  fact and must not be reported as a zero reading.
- "`--warn-avg10 X` … finding `PRESSURE_HIGH` when avg10 ≥ X on … `full` of memory/io/irq" →
  upstream: irq has only a `full` average to threshold, which is why the contract lists irq
  under `full` and not under `some`.
- "resident trigger watcher and cgroup-scoped CPU/IO/IRQ pressure stay Frontier" → upstream
  shows the irq trigger path is restricted to `PSI_IRQ_FULL` and that the per-cgroup `irq.pressure`
  file exists upstream but is not read by this round's one-shot reader; the Frontier boundary is
  upstream-consistent, not invented here.

**Under-determines (this commit does not state them):** the `--warn-avg10` default value
(10.0), the `PRESSURE_*` verdict names, the `total_delta_us` / `stall_ratio` arithmetic and
the `--interval` bound — all of these are mori's own tool contract, not kernel text. The
commit also says nothing about the `cpu` `full` line at system level (`full_system_undefined`);
that is the subject of a separate source seat.

**Contradicts:** nothing in the contract that this commit touches.
