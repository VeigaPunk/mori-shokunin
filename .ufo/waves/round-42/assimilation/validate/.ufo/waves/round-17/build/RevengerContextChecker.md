# Reconstruction: `mori-round16-context-check.py`

## Scope and method

Static repository reads only: the target script, its r16 author report and receipts, the r15 verifier’s routed closure queue, the r16 lesson, and the r17 context/receipts. No shell command, gate, test/selftest, live journal query, URL fetch, installation, or runtime experiment was performed for this report. The exit codes below are recorded in existing evidence files, not runs by this reviewer.

## Reconstructed design intent

This is a *pre-dispatch context-completeness advisory*, not a behavior-control mechanism. The script’s own contract says it checks for required restrictions in spec text, cannot prevent a seat from violating them, and cannot detect a clause that is present but contradicted; runtime prevention is explicitly false (`tools/mori-round16-context-check.py:43-51`). The intended benefit is narrower: make important safety/scope instructions visibly present in the shared wave context before dispatch, and report which clause is missing. That boundary matters because the r15 queue explicitly warned not to describe an admonition as a tested preventive repair (`corpus/lessons/round-15-verifier-spotcheck.md:260-266`), while r16 later documented repeated `/tmp` writes and live journal queries despite instructions, concluding that admonition is not runtime prevention (`corpus/lessons/round-16.md:47-53,78-79`).

Mechanically, it reads a JSON spec, recursively collects string values under keys literally named `context` (or accepts a top-level string), and requires every collected context to satisfy every clause (`tools/mori-round16-context-check.py:223-243,271-308`). No context is a missing-context failure. Clauses are regex phrase-presence checks: alternatives within a group are OR; all groups for a clause are required (`:78-80,81-202`). The grouped checks require more than a bare topic mention where that matters—for example, a broadcast prohibition plus exact-ID wording, or a target (`/tmp`, credentials, `journal`) plus the corresponding ban. The `live`/`journal` clause is deliberately more specific than a generic “no network/live reads” phrase (`:26-33,173-199`). The code does not establish semantic equivalence, authorship, or compliance.

The result is one JSON object with finding ID, missing clause IDs/counts, and a spec hash; spec text is not echoed (`:35-41,53-56,276-308`). Its selftest checks positive input shapes and that dropping each isolated clause yields that clause’s missing ID; it tests the checker’s matching behavior, not whether recipients obey instructions (`:315-360,407-429`). The script explicitly warns that selftest existence is not execution permission (`:58-62`), reflecting the r15 correction that implementing a selftest arm did not authorize running it (`corpus/lessons/round-15-verifier-spotcheck.md:274-281`).

## How clause selection follows the evidence

The r16 author report records an initial six-clause set: no broadcast/exact ID, report-location resolution, no unapproved verification, pacman pause, credential prohibition, and write scope (`.ufo/waves/round-16/build/ContextGuard.md:8-22`). These clauses combine known coordination/provenance failures with the explicit safety and write-boundary rules in the assigned shared context. The report says its matching phrases were drawn from the actual r16 spec/task context (`ContextGuard.md:75-90`).

Two further clauses were requested by L1 in the same wave: `no_live_journal_queries` and `no_tmp_probe_outputs` (`ContextGuard.md:56-73`). They were not arbitrary broadenings: r16’s lesson records live `journalctl` probes (M8/M9), deliberate `/tmp` scratch/output (M7/M9/M14 and other disclosures), and other process deviations (`corpus/lessons/round-16.md:51-59,62-65`). The same lesson says that all such probes are inadmissible and that admonitions do not prevent recurrence (`:78-79`). The exact live-journal ban was made stricter than “no live/network reads”: the r16 author report says the original wave context lacked the explicit clause and that the context-only corrected fixture was the one that satisfied it (`ContextGuard.md:63-73`). This is a useful example of the gate’s purpose—finding a missing instruction in the text—not proof the instruction will be followed.

`lane_report_resolution` is supported by r16’s observed misroot: two reports were written under the fleet root despite absolute-path instructions (`corpus/lessons/round-16.md:242-249`). The r16 review also recorded report-path/repository ambiguity as a citation hygiene issue (`.ufo/waves/round-16/build/ReviewLesson.md:45`). `write_scope` is likewise consistent with the reported overwrite of another seat’s owned lesson file (`corpus/lessons/round-16.md:64,167`). Pacman pause and credential prohibition are explicit boundary clauses; the available r16 reports do not establish that either arose from one of closure items 1–3, so I do not attribute them to those items.

The checker’s limited but concrete signal is visible in retained receipts: r16’s original context received `CONTEXT_MISSING` for `no_live_journal_queries` (recorded exit 1), while the context-only corrected fixture received `CONTEXT_OK` (recorded exit 0) (`.ufo/waves/round-16/evidence/context-original.json:13-15`; `context-corrected.json:13-15`). The r17 original context receipt was missing `no_tmp_probe_outputs`, and the corrected receipt was `CONTEXT_OK` (both state `claims_runtime_prevention: false`) (`.ufo/waves/round-17/evidence/context-check-wave1-original.json:1`; `context-check-wave1.json:1`). These receipts show static context detection/correction, not runtime enforcement.

The other clauses are separately supported by the write-path/safety context and r16 scope incidents; they should not be represented as direct consequences of closure items 1–3.

## Confidence and limits

High confidence on the advisory/non-prevention boundary and the three item-to-clause mappings: both the tool contract and the numbered closure mapping state them directly, and retained receipts demonstrate the static result. High confidence that the two rev2 clauses followed the r16 live-journal/`/tmp` deviations, based on the author report and lesson. Moderate confidence on the broader historical origin of every initial clause: the author report ties their regex phrases to the existing wave context, but does not give a separate incident-to-clause ledger for every restriction. No inference here upgrades static context presence to actual compliance.
