## Semantic ambiguities L1 must freeze

1. **Scope of "line".** Freeze: the `line` field only, in every hit-bearing list (`hits`, `unallowlisted_hits`, `allowlisted_hits`; `line:null` aux rows are R18-adjacent). `line_sha256` is R07, `class` is R09, content changes are tree mutations, not receipt mutations. Value must stay a valid int ≥1 or the arm is R18.
2. **Receipt-internal inconsistency classification.** The frozen `hits`-only mutation makes the receipt internally inconsistent (`hits` disagrees with `allowlisted_hits`). The contract calls exit 1 "valid receipt disagrees with recomputation" and exit 2 "schema inconsistencies fail closed" — an internally inconsistent receipt is arguably not "valid". The frozen arm embeds the MISMATCH choice; the candidate also resolves it to MISMATCH (each list is compared to recomputation independently). **Freeze: every hit-bearing list is validated independently against its recomputed multiset; cross-list receipt inconsistency is MISMATCH, never SETUP.** With L8a/L8b/L8d committed, the choice becomes immaterial for the strengthened arms.
3. **Duplicate precedence.** A `line` mutation that lands on an existing 4-tuple produces a duplicate receipt hit → exit 2, not 1. Freeze ordering: type/schema (incl. duplicate) rejection before identity reconciliation.
4. **Multiset vs order.** Line swaps between hits sharing `(path,class,sha)` are no-ops; order permutations are no-ops. Freeze multiset equality; N-perm pins it.
5. **`raw_unallowlisted` vs `scanner_unallowlisted` are degenerate twins** (adjacent observation, denominators are owned by other seats): under gate semantics unallowlisted excludes non-author by construction, so the candidate's two fields are always equal; the contract names both as if distinct. Not an R08 blocker, flagged because L8r's expected values depend on it.

## Superficial-pass risks (summary)

The frozen arm alone admits one false pass: an implementation that **never recomputes from the measured tree** and only checks receipt-internal consistency returns 1 on every frozen R05–R10 arm (each frozen mutation is internally inconsistent) while providing zero reconciliation capability — the exact thing C1 claims. L8a/L8b/L8d/L8r close it by mutating all lists that redundantly carry the tuple. Secondary classes: hits-only validators (closed by a partition-list-only arm, which is inherently internal-inconsistent, so it depends on freeze #2), scanner-only comparators (closed by L8d), 3-tuple comparators (already killed by the frozen arm). The candidate implementation does not exhibit any of these defects; its residual gap is the missing MISMATCH selftest arm — add L8a as the selftest's mismatch exemplar (assertions: exit 1, `RETENTION_RECONCILIATION_MISMATCH`, `privacy_clearance is false`, stderr empty).
