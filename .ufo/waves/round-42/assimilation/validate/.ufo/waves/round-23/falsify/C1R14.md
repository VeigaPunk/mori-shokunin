## 9. Findings by severity

### F-1 — LOW / informational (predicate weakness; **inherited** from r22, no observed harm)

**R14 as frozen cannot prove that the ancestry guard exists.** `record()` asserts only
`exit==2 ∧ finding_id==SETUP ∧ stderr==''`; it never reads `error`.

*Concrete counterexample (static, not executed):* delete the single line
`tools/mori-retention-reconcile.py:175`
(`require(git(repo,'merge-base','--is-ancestor',measured,revision,ok=(0,1)).returncode==0,
'measured_not_ancestor')`), leaving everything else intact, and re-run the frozen suite:

1. R14's arm now falls through L175 and reaches **L196**
   (`require(argv.count('--rev')==1 and argv[argv.index('--rev')+1]==measured,
   'receipt_revision_conflict')`). Because the `diverged` fixture rewrites
   `wrapper['measured_revision']` (builder L92) but **not** `wrapper['argv']` (builder L76–L77),
   argv's `--rev` still holds the pre-divergence `measured`, so L196 fails instead.
   Result for R14's arm: **exit 2, `RETENTION_RECONCILIATION_SETUP`, stderr empty**, `error`
   changing `measured_not_ancestor → receipt_revision_conflict`. **R14 still passes.**
2. No other requirement in the 26 detects the deletion. Per arm (traced from the frozen builder):
   * R13 (`invalid-revision`) fails at L173 (`receipt_revision`) — before L175 is reached;
   * R17 (`malformed`), R20 (`unsafe_input_path`), R21 (`input_not_regular`) fail before L175;
   * R15, R16, R18, R19 and all check-shape arms (R01–R12, R22–R24, R26) use a `measured` that
     **is** an ancestor of `revision`, so L175 was a no-op for them and removing it changes
     nothing;
   * R25 inspects only `schema`/key presence.
   ⇒ the suite would still read **26/26** with L175 deleted.
3. The observable safety property is nevertheless *preserved for this fixture* (a divergent
   receipt is still rejected as a setup error, never reconciled, never granted clearance). What
   is lost is that the frozen 26-requirement denominator cannot demonstrate the guard.
4. The hazard the guard actually carries is reachable in principle. Under the mutant, a
   **coherent hostile receipt** — one whose `measured_revision`, inner `commit` and argv `--rev`
   all name an unrelated commit `X` outside the audited history, whose policy/allowlist bytes at
   `X` equal those at `revision`, and whose inner `stdout` matches a scan of `X`'s tree — passes
   L171–L173, L176–L177 and L196–L199, and would reconcile with `RETENTION_RECONCILED` / exit 0
   while reporting `input_revision=revision`. The counters it emits would be computed by
   `hits=scan(repo,measured,classes)` over **`X`'s tree**, not over the audited revision's tree —
   which is precisely the class of confusion the ancestry check exists to prevent. The frozen
   `diverged` fixture cannot express that shape (its `argv['--rev']` is left pointing at the
   pre-divergence commit), so R14 cannot detect the guard's removal.
5. **Bound on severity:** the *supplementary* source-delta guard does close this. `C21`
   (driver) requires the production file to equal the transformed baseline exactly; an
   L175-deletion mutant has a different sha256 and is rejected (`C22` demonstrates the guard
   discriminates). So the gap is in the **original-26 denominator's discriminating power**, not
   in the round's overall protection, and the defect is **inherited verbatim from r22**
   (r22 oracle L54 is byte-identical) — i.e. **not a C1 regression** and not something this
   wave's pre-registered bytes may be edited to fix.

*Status at production:* the guard **is** present and **does** fire — `error="measured_not_ancestor"`
in every before and after receipt for the `diverged` arm.

R14's arm output is a *setup envelope*, so the C1 rename cannot reach it (the removed key lived

is "R14's *observable contract* (exit/finding/stderr) is unchanged, and the schema field inside

### F-3 — INFORMATIONAL (no finding; recorded for closure)

R14 is **not** the requirement that carries the C1 claim. The C1 headline (`misleading_alias_runs`
8→0, schema v1→v2 on every parsed run, 25/26 → 26/26) is evidenced by **R25**; R14 is a control
that stayed green in both arms. Reporting R14's green as evidence for the cutover would be a
category error.

## 11. Conclusion

predicate, identical fixture builder, unchanged rejecting code line, `exit 2` /
`RETENTION_RECONCILIATION_SETUP` / empty stderr in both arms, and a same-instance replay in

bounded to LOW/informational because the supplementary byte-delta guard rejects that mutant and
because the weakness is inherited verbatim from the r22 frozen predicate; it must not be
"repaired" inside this wave, whose frozen case/rule/oracle bytes are immutable. It is recorded
as a candidate for a future round's requirement-authoring stage (an arm-level `error` assertion,
or a fixture that keeps the argv `--rev` consistent with the diverged `measured_revision`).
