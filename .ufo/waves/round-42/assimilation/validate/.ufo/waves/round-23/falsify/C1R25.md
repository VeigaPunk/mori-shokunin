The predicate itself lives in the sealed oracle `.ufo/waves/round-23/oracle-rename.py`
(sha256 `a55b2b50d3e7447a1d5312c8b066a13137a6a6895f0343b3240ebf081d97c5f2`; identical at seal

`f3dc07c0bf423cc1947d0ffa91afa9ce236fbe3c` and in the worktree — all four digests recomputed by me


Five properties of this predicate, each load-bearing for the verdict:

1. **Fixture-independent.** R25 reads *only* `data['runs'][*]['stdout']`. It never touches the
   fixture, the policy/allowlist bytes, or the receipt. (Contrast R26, which reads the fixture's
   committed blobs.) Consequence: R25's before/after comparison stays meaningful even though the
   oracle generates **separate** fixture roots for its two arms (`before-fixtures/` vs
   `after-fixtures/` — I verified the trees are distinct directories, and that
   `valid/policy.json` and `valid/allowlist.json` are byte-identical between them while
   `valid/receipt.json` differs only in the absolute repo path baked into its `argv`).
2. **Alias test is top-level key membership.** `'raw_unallowlisted' in o` on a `dict` is a
   *top-level* membership test. → **M1** in §4.
3. **Schema test is universal over `parsed`, but `parsed` is filtered.** Only stdout that parses
   to a JSON **object** enters `parsed`; a non-object stdout is silently dropped. `bool(parsed)`
   makes the all-non-object case fail closed, but a *mixed* set is not closed. → **L1** in §5.
4. **The alias and schema conditions are independent conjuncts.** R25's red does **not** isolate
   the alias. → **L2** in §5.
5. **R25 sits in the roster at the right slot.** `results.insert(24, …)` places R25 between R24 and
   R26; I confirmed from both committed observation files that the emitted id order is exactly
   `R01…R26` with R25 at index 24 (§3, table).

**Predicate identity vs the r22 oracle.** `diff` of `.ufo/waves/round-22/oracle-reconcile-v2.py`
(sha256 `dcd1c7c656ea8b2e266f88762bf5540e42e41c78078a4b8b11f41e23670d8adb`) against
`oracle-rename.py` shows R25/R26 are **new** rows; R01–R24 are the r22 predicates with the
`raw_unallowlisted → scanner_unallowlisted` substitution in R02/R11/R12 only. R25 has **no**
r22 antecedent and **no** semantic content: it asserts nothing about counters, exit codes, finding
ids, or identity lists.

**Contract wording vs the frozen predicate.** Contract §C1 states R25 as "*every oracle run whose
stdout parses as a JSON object has `schema == "mori-retention-reconciliation-v2"` and no key
`raw_unallowlisted`*". The implementation matches that wording literally. The contract's
*separate* clause — "`SCHEMA` becomes `mori-retention-reconciliation-v2` in **every** output
(check, setup error, selftest)" — reaches **beyond** R25: the oracle only ever invokes the `check`
subcommand, so the selftest output is never in `data['runs']`. → **M2** in §4.

## 4. Findings — severity ordered

### M1 (MEDIUM, predicate-level; unreachable in the delivered artifact) — R25's alias test is **top-level key membership only**

`'raw_unallowlisted' in o` on a `dict` tests the **top level** of the parsed object. I replayed the
frozen predicate logic verbatim on hand-built stdout dictionaries (no tool, no oracle, no git, no
fixture — pure predicate replay):

| synthetic stdout | R25 verdict |
|---|---|
| `{"schema":"mori-retention-reconciliation-v2","raw_unallowlisted":4}` | **pass=False** (misleading=1) — detected ✔ |
| `{"schema":"mori-retention-reconciliation-v2","stats":{"raw_unallowlisted":4}}` | **pass=True** (misleading=0) — **missed** ✘ |
| `{"schema":"mori-retention-reconciliation-v2","note":"raw_unallowlisted"}` | **pass=True** (misleading=0) — **missed** ✘ |
| `{"schema":"mori-retention-reconciliation-v2","raw_hits":[{"path":"a","raw_unallowlisted":4}]}` | **pass=True** (misleading=0) — **missed** ✘ |
| `{"schema":"mori-retention-reconciliation-v2","scanner_unallowlisted":1}` | pass=True — clean ✔ |
| `[1,2,3]` (non-object stdout) | pass=False (parsed=0, `bool(parsed)` fail-closed) ✔ |
| `{"finding_id":"RETENTION_RECONCILED"}` (no schema key) | pass=False (schema_v2=0 ≠ parsed=1) ✔ |

**Concrete counterexample:** a producer that keeps the misleading alias but moves it one level down
(`stats.raw_unallowlisted`) or renders it as a value string, or hides it inside a hit object,
**passes R25** — the requirement is red only for the top-level spelling. Note this is *not* an
inconsistency with the contract wording ("no key `raw_unallowlisted`" is unqualified), so the
frozen predicate is narrower than its own prose.

**Why it does not harm the delivered artifact.** The alias is produced by exactly one source
fragment. In the entering blob the token `raw_unallowlisted` occurs **1** time (line 234) and in
the final pinned blob it occurs **0** times (I recomputed both counts over the extracted bytes).
With the token absent from the entire file, no output shape — top-level, nested, or value — can
carry it. The source-delta guard (§5/§6) is what closes M1, **not R25**. R25 alone would not have
caught a nested alias; the suite does.

### M2 (MEDIUM, scope) — R25 does not cover the `--selftest` output path

Contract §C1 requires schema v2 "in **every** output (check, setup error, selftest)". The oracle's
`invoke()` (line 38–43) constructs only `check` invocations; `grep selftest` over
`oracle-rename.py` returns **no match**. R25's `parsed` therefore contains 18 `check`-mode stdouts
and **no** selftest stdout. So the selftest half of the contract's schema clause is discharged
**only** by the supplementary guard `C24.c1_selftest_schema` (driver lines 811–847), which measured:
entering selftest `schema` = `mori-retention-reconciliation-v1`, measured selftest `schema` =
`mori-retention-reconciliation-v2`, `alias_present` false in both, exit 0 both, `passed` 4/4 both,
identical payload otherwise. C24 is reported **outside** the original-26 denominator
(`denominators.c1_supplementary_guards = 5`), consistent with the amendment's "Original26 plus
these supplementary guards remain separately reported, never silently redefining the original26
denominator."

**Consequence for any claim built on R25 alone:** "R25 green ⇒ the C1 schema cutover holds on
every output surface" is **false as stated**; it holds on the check/setup surfaces only. Cite C24
for the selftest surface. This is a *reporting* gap, not a measurement gap.

### M3 (LOW) — the frozen expectation blocks are decorative; enforcement is by hardcoded constants

`frozen/c1-requirements.json` carries `before_expected` / `after_expected`, but **no executed
Python in the wave reads either block** — `grep -r "before_expected|after_expected"` over
`.ufo/waves/round-23` matches only markdown reports, never a `.py`. The driver instead hardcodes
`C1_BEFORE_UNMET = ['R25']` (line 109) and `C1_REQUIREMENT_COUNT = 26` (line 108) and enforces
its own recomputation (C17/C19). The numeric outcomes agree — frozen says alias ">0" and unmet
`['R25']`, and the driver measures 8 (>0) and `['R25']` — so **nothing is misstated today**. But
the pre-registered *text* is not the operative instrument: a future drift between the frozen JSON's
expectation blocks and the driver's constants would fire **no check**. The driver's own bytes are
sealed (`sha256 5c12fdc056309966d3e716d25e3427a7908056595383f0353655b42282fdfbcd`, identical at
seal and in the worktree — C13 True), so the constants cannot be retuned post-seal; only the
frozen JSON and the constants could disagree, and nothing would notice.

### M4 (LOW, boundary — concerns R02, not R25, but bears on "unchanged semantic requirements")

The mechanical substitution degraded R02 into a tautology. r22: `v['raw_unallowlisted']==1 and
v['scanner_unallowlisted']==1`; r23: `v['scanner_unallowlisted']==1 and v['scanner_unallowlisted']==1`
(`oracle-rename.py:52`) — the same conjunct twice. The r22 form cross-checked that the two v1
names carried the *same* value; the r23 form cannot. In the **before** arm this means r23's R02 no
longer proves the v1 tool's two names agreed. This is already recorded inside the wave
(`build/DraftLesson/mistakes.md` M8) and by sibling seats; I flag it only because it is the one
place where "R01–R24 are the unchanged semantic requirements" is not literally true of the
*predicate bodies*. It does not affect R25's verdict and it does not weaken the after-arm
semantics, where the alias no longer exists to disagree.

## 5. What R25 does **not** establish (limits of the "no harm" claim)

* **L1 — parsed-run coverage is not closed.** R25 never asserts `parsed_runs == len(data['runs'])`,
  and neither does driver C20 (`schema_v2_runs == parsed_runs and parsed_runs > 0`). An arm whose
  stdout is valid JSON but **not an object** is silently excluded from `parsed` and therefore from
  both R25 conjuncts. Measured: `parsed_runs` = 18 = number of runs in both arms, so **no gap
  materialised**; the predicate is nonetheless permissive in this dimension. (`bool(parsed)` does
  make the all-non-object case fail closed.)
* **L2 — R25's before-red is over-determined.** Before the cutover both conjuncts failed at once:
  `misleading_alias_runs` = 8 (alias present in 8 of 18 arms) **and** `schema_v2_runs` = 0 of 18
  (no arm was v2). R25 is a conjunction, so its red does **not** attribute the failure to the
  alias. The alias-specific evidence is the separate `misleading_alias_runs` counter (8 → 0),
  which the driver recomputes independently (C19) and which the real control corroborates
  (C26: alias value 4 before, absent after).
* **L3 — R25 cannot corroborate any semantic row.** It reads no counter, exit code, finding id or
  identity list. Conversely the other 25 rows are **green in both arms** and therefore cannot
  corroborate the cutover either: R25 is the *only* row that flips, and the semantic rows'
  discriminative work is done by the same-instance replay and the byte guard, not by R25.
* **L4 — R25 is not a whole-output identity check.** It is a two-key surface check. The claim
  "no other output key, value, exit code or finding id changed" rests on `C23.c1_same_instance_output_equivalence`
  (measured: 18 arms, `differences` empty, `identical_apart_from_special_keys` true for all 18;
  key sets equal except the removed alias; `argv` equal) and on `C21.c1_source_byte_guard`.
  R25 alone proves neither.

   "26/26" as covering "every output" is wrong; C24 is the carrier.
3. **The frozen expectation blocks are not enforced** (M3). Today's numbers coincide; the
   coincidence is not check-enforced.
4. **Parsed-run coverage is unclosed** (L1) and **R25's red is over-determined** (L2). Neither
   materialised (18/18 parsed both arms; alias counter measured separately).
5. **R02's predicate body is a tautology after substitution** (M4). Already logged in the wave's
   own draft lesson (M8) and in sibling reports; recorded here for the R25 boundary only.
6. **Not exercised by me, by instruction and by scope**: the production tool, the oracle, the
   driver, the r22 reproduction at `da40bb20f81da125d798f73cd1653655be1255ca`, the r22
   refinement checks (which read the removed key — expected to fail against a post-cutover tool and
   reproducible only in a checkout of their bound revision, per the amendment), any quota surface,

7. **Out of scope for this seat**: the C2 strict red (`C34.c2_after_every_case_matches` False,
   `C30.c2_oracle_real_control_agrees` False; the frozen contradiction at
   `evidence/frozen-contradiction.json`). Nothing in this report touches C2, and no C1 byte,
