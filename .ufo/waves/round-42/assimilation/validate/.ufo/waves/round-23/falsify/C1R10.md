**Mutation sensitivity of R10 (does the requirement actually discriminate?).** Reading the
comparison site, R10 fails if the tool stops comparing the counter
(`('metric',len(unallowed))` removed ⇒ `differences == []` ⇒ exit 0 `RETENTION_RECONCILED`

vacuous, and mis-comparisons are caught by the neighbouring requirements of the same

## 7. Findings by severity

**No counterexample found. R10 stands, as a *bounded* agreement (not a blanket no-harm).**

### Medium — R10's predicate does not pin the *cause* of the mismatch (requirement-level observability gap)

R10 asserts only `exit==1`, `finding_id==RETENTION_RECONCILIATION_MISMATCH`, `stderr==''`.
It never asserts that the mismatch is attributable to the `metric` counter. A tool that
reported the `metric` arm as a mismatch for the *wrong* reason (e.g. `differences ==
['hits']`) would still satisfy R10. Evidence that the attribution is in fact correct exists,
but **outside** the frozen requirement:
* the recorded stdout of the `metric` arm carries the tool's own `"differences":["metric"]`
  (`evidence/measure4/c1-after-observed.json`, `runs[variant=="metric"]`; and
  `c1-replay-entering-06.json` / `c1-replay-measured-06.json`);
* the source-delta guard proves the comparison site is byte-identical to the r22-validated
  source.

So this is a *specification-strength* finding, not a false green in the measured state. It
also cannot be closed retroactively: `frozen/c1-requirements.json` and
`oracle-rename.py` are sealed and immutable, and R10's predicate may not be rewritten to
add a cause check (that would be result-driven rewriting of a frozen expectation). Any
future strengthening must be a new, separately numbered requirement.

### Low — the C1 tool selftest does not exercise the `metric` arm

`c1-selftest-measured.json` (exit 0, `{"finding_id":"RECONCILE_SELFTEST_PASS","passed":4,
"total":4,"schema":"mori-retention-reconciliation-v2"}`) exercises only the tool's own
four internal cases (base, wrong `hits`, `../allow.json` path escape, unknown flag). It does
not exercise a counter-mismatch arm. The `metric` arm therefore rests entirely on the
oracle run, not on the selftest — relevant when reading "selftest 4/4" as if it covered the
C1 requirement surface (it does not).

### Low — R10's sensitivity to a *mis-attribution* mutation is carried by neighbouring requirements

Because R10 has no cause predicate, the "the mismatch is the counter" claim is carried by
R01/R02/R11/R12 (which pin `scanner_unallowlisted`, `raw_total`, `non_author`) plus the
source-delta guard. Any future revision of the tool must re-run the whole C1 oracle, not
just R10, to preserve that chain.

### Informational — no production/frozen/oracle byte was touched; nothing executed

The only file I wrote is this report. No tool install/update was performed (no pacman/uv/
cargo/npm activity, so no version/channel/reason record applies). I ran no driver, no
selftest, no fixture, no quota probe, and no host quota/privilege interface; every number
above is either recomputed from committed bytes by read-only `git show`/`sha256sum` or
quoted from an already-committed receipt, with the source named.

## 9. Verdict

**R10 — bounded agree (not falsified).** With the frozen predicate read verbatim
(`record('R10','metric',1,'RETENTION_RECONCILIATION_MISMATCH')`), the r22 fixture arm
(`result['metric']=0` against the builder's own `metric=len(unallowed)`=1), and the
schema-v2 tool proven byte-equal to the entering source after exactly the two frozen
transformations, the arm's only difference is the counter, so the tool must report
`RETENTION_RECONCILIATION_MISMATCH` with exit 1 and empty stderr — matching both the
committed `measure4` receipts and my independent static derivation. R10 is *not* part of
the R25 API cutover: it passes identically before and after (`c1-before-observed.json` and
`c1-after-observed.json` both record R10 `pass:true`, `differences:['metric']`), and the
only C1 requirement that flips is R25.

Residual, unresolved-by-design: R10's predicate does not bind the *cause* of the mismatch
(Medium, §7) and the tool's own selftest does not cover this arm (Low, §7). Neither is a
false green in the measured state; both are named gaps for the parent, not grounds to
rewrite a frozen expectation.
