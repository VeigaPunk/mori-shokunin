## 7. Findings

### F1 — MEDIUM (calibration, inherited): R15 is exit-class evidence; it cannot fail when the guard it names is deleted

**Where:** `oracle-rename.py:58` + `:44-49` (no `error`/key-set assertion) against
`tools/mori-retention-reconcile.py:176-177` and `:199`; fixture `fixture-builder-v2.py:73` and `:97`.

**Mechanism.** The `policy-changed` arm carries two independent exit-2 causes:

* (a) *target* — the M→I byte comparison at `:176-177` raises `policy_changed`;
* (b) *incidental* — the receipt's `policy_sha256` (sha256 of `P`, builder `:73`) no longer matches
  the input-revision policy blob (sha256 of `P+"\n"`), so `:199` raises `receipt_policy_digest`.

Both produce the identical observable R15 asserts: exit 2, `RETENTION_RECONCILIATION_SETUP`, empty
stderr.

**Concrete counterexample (static trace; not executed).** Let `M1` = the production source with the
two-line guard at `:176-177` deleted and nothing else changed. Under `M1`, the `policy-changed` arm
still reaches `:199` (the policy parses identically, the allowlist parses, the receipt's argv
bindings and counters are unchanged) and still exits 2 with
`finding_id=RETENTION_RECONCILIATION_SETUP` and empty stderr. **Frozen R15 therefore still passes
under `M1` — R15 cannot fail when the very guard it names is deleted.** [INFERENCE: static trace over
the shipped source; not executed by me. Independently reached by the r22 seat
`.ufo/waves/round-22/falsify/FixturePolicyChanged.md`, which reports the same non-fail-capability
and the same asymmetry with R16.]

**Why it matters.** With the guard gone, `M1` scans the *measured* tree with the *input* revision's
policy classes (`tools/mori-retention-reconcile.py:207`, `hits=scan(repo,measured,classes)`) and
never notices that the policy changed between M and I — the shape the r22 contract explicitly bans
("Policy and allowlist bytes at input revision must equal bytes at target revision; mismatches
unevaluable, not silently current policy applied historically", `round-22/contract.md:11`). If the
receipt digest is rebound to
the changed bytes (the r22 co-evolved case `policy-change-digest-updated`,
`round-22/refinement-reconcile.py:113-115`, which sets `value['policy_sha256']=digest(P+"\n")`),
`M1` reconciles and returns **exit 0 `RETENTION_RECONCILED`** for an arm whose policy was changed —
i.e. a silent false-green on the historical-policy axis. The shipped tool is not in that state
(measured `error:"policy_changed"`), but the frozen R15 alone does not prove it.

**Scope of the defect.** Inherited from r22, **not** introduced by C1: the C1 diff touches neither
`:176-177` nor `:199` nor the fixture nor R15's predicate. The r23 wave's **supplementary** guards
do close it at wave level: C21/C22 (byte-exact source, `measure-round23-v2.py:688`,`:711`) reject
`M1` outright, and the r22 co-evolved refinement case kills it — but the r23 driver does **not**
run the r22 refinement harness (no `refinement` reference anywhere in `measure-round23-v2.py`), and
the r22 refinement harness is not schema-safe for the v2 tool anyway (it reads `raw_unallowlisted`
in five cases, `round-22/refinement-reconcile.py:186,187,188,191,192` — exactly the "five refinement
checks" the amendment names as breaking on the new API).

**Consequence for the headline.** R15 contributes 1/26 of "26/26" while being exit-class-only. The
honest description of R15 is: *the tool exits 2 with a setup finding when the policy differs
between the measured and the input revision*; the *reason* attribution (`policy_changed`) is
attested by the wave's measured receipts, not by R15's predicate.

**Smallest safe correction (not applied by me; frozen bytes untouched).** Re-express the two
policy-change cases of the co-evolved harness against the v2 API — a pure field substitution
`raw_unallowlisted`→`scanner_unallowlisted` in the five alias-reading cases, which is value-preserving
because the v1 producer emitted `raw_unallowlisted` and `scanner_unallowlisted` from the same
`len(unallowed)` (see the diff in §5) — and run `policy-change` and `policy-change-digest-updated`
against the v2 tool, reporting them **separately from the original-26 denominator** (as the
amendment requires for the supplementary guards). No frozen file changes.

### F2 — LOW (provenance, inherited): the fixture's `expected_policy_sha256` mislabels the `policy-changed` arm

`fixture-builder-v2.py:105` returns `digest(files[POLICY])` = sha256(`P`) for every variant, but for
`policy-changed` the **input revision** carries sha256(`P+"\n"`). Measured in the wave's receipts:
`fixture.expected_policy_sha256 = 38ec02216438277b7d79ccd0d058b482ab7a75099f65861227d5eed4e9c743b6`
in both `c1-before-observed.json` and `c1-after-observed.json` for that arm. No pass is affected —
R15 does not consume the field, and R24 runs on the `valid` arm only — but the retained oracle
record mislabels that arm's input-policy digest, and any future consumer of `runs[].fixture` would
inherit the error. Not fixable without editing a hash-bound frozen builder; it should be *labelled*,
not silently corrected.

### F3 — LOW (verification gap): `privacy_clearance == false` is unasserted on the R15 setup envelope

No frozen requirement asserts `privacy_clearance is False` for a setup-shaped output. R02/R11/R12/R23
assert it only for check-shaped outputs; R25 asserts only schema and alias absence. The shipped
setup path hard-codes `privacy_clearance: False` (`tools/mori-retention-reconcile.py:287`, `:289`)
and C21 pins those bytes, so the shipped code is safe — but an implementation that emitted
`privacy_clearance: true` on a setup envelope would satisfy all 26 requirements. C24
(`measure-round23-v2.py:844`) covers the selftest output only, and C25 the real check output only.

### F4 — INFO (bound, no defect): R15's reason token is attested by measurement, not by the predicate

The `error` token is not part of R15's predicate, yet the wave's committed receipts show
`error:"policy_changed"` for the arm both before and after the cutover, and C23 enforces its
value-equality across the cutover. The reason is therefore evidenced — but by the receipts and by
C23's equivalence, **not** by R15. Any claim of the form "R15 proves the changed-policy guard"
would overstate the frozen denominator.
