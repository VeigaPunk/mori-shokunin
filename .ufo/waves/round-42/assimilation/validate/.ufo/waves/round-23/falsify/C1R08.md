## Findings by severity

**No high or medium findings.** R08 is not falsified.

* **F-08-01 (low, residual — predicate resolution limit, not a production defect).** R08 asserts only (exit 1, `RETENTION_RECONCILIATION_MISMATCH`, empty stderr). Because the fixture aliases hit objects, the `line` arm's non-empty `differences` is produced by `hits` **and** `allowlisted_hits`. Concrete counterexample shape: a mutant that compares `hits` with a line-insensitive 3-tuple key while keeping the line-sensitive `hit_key` for `allowlisted_hits` would still yield `differences=['allowlisted_hits']` → exit 1 → **R08 green**, although the `hits` line comparison is broken. (A *global* removal of `line` from `hit_key` is caught: all three comparisons become line-insensitive ⇒ no differences ⇒ `RETENTION_RECONCILED`/exit 0 ⇒ R08 red.) No other requirement in the sealed set pins the `hits` line comparison specifically: R05/R06/R07/R09 are caught by count/path/class/sha, R03/R04/R22/R24 do not observe receipt-vs-scan identity per line. Impact for this revision is nil: the byte-exact source guard (A5) forbids any such code divergence, and the shipped tool uses one shared `hit_key` for all three fields (tool:225). Recommendation for the *next* revision only (not actionable here, and explicitly out of scope for a frozen round): a dedicated arm that mutates a line number inside `unallowlisted_hits` only, or an assertion on `differences` content.
* **F-08-02 (low, residual — diagnostic granularity).** `differences` is field-level; the tool does not localize *which* hit/line mismatched (the tampered receipt points at `policy.json` line 14, which contains no hit). No sealed requirement demands localization, and R23 only forbids leaking sample content, so this is a bounded observation, not a violation.
* **F-08-03 (informational — fixture arm coverage).** The `line` arm never exercises a line tamper visible only in `unallowlisted_hits`, because `hits[0]` is the `policy.json` hit, which is shared with `allowlisted_hits` only.
