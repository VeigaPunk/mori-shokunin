## 8. Falsification attempts (each closed)

1. *Could R21 exit 2 for an unrelated cause, making it a vacuous green?* No: the recorded error token
   is `input_not_regular`, emitted only by the mode test at `tools/mori-retention-reconcile.py:90`;
   the same fixture with a regular receipt (R01/R02, same builder, same policy/allowlist) exits 0.
2. *Could R21 pass vacuously?* `record()` requires exit==2 **and** the finding id **and** empty stderr;
   a crash (traceback on stderr) or a non-JSON stdout fails the arm.
3. *Could the symlink have been committed as a regular blob (`core.symlinks=false`), turning R21 into
   a JSON-parse test?* No: the retained fixture's `git ls-tree` shows mode `120000` for
   `receipt.json`, and the observed token is `input_not_regular` (a regular blob would have given
   `invalid_json`). The builder also neutralises ambient git config.
4. *Could the oracle's R21 predicate have drifted from the frozen r22 one?* No — full-file diff shows
   the R21 line as unchanged context and the `record()` helper unchanged.
5. *Could the fixture have co-evolved with the implementation?* No — the builder is the r22 frozen
   file, imported by path, and its sha256 equals the pin frozen in `c1-requirements.json` before the
   implementation existed.
6. *Could the tool follow the symlink and read `allowed.txt` as the receipt?* No — the mode test
   precedes `cat-file blob`; the error token proves the read never happened.
7. *Could the cutover have broken R21 via the source delta?* No — the guard derivation reproduces the
   production blob byte-exactly from the entering blob with exactly the two declared substitutions,
   and neither touches `committed()`, `tree()` or the `Invalid` handler.

## 9. Residual risk and verification gaps (bounded, no scope change proposed)

1. **The frozen R21 predicate is weaker than the behaviour it stands for.** It asserts exit+finding+
   empty stderr only; it does not assert the `error` token, so a future tool that refused this arm
   for an unrelated reason would still satisfy R21. The recorded `input_not_regular` token is the
   specific witness for *this* revision, but that specificity is **not** inside the frozen
   requirement. Mitigation available without touching frozen bytes: none needed for C1 (the token is
   retained in the observation JSON); a future round may wish to strengthen the predicate.
2. **The R21 arm's defining worktree input is not directly content-addressed.** The oracle's retained
   manifest filters `not x.is_symlink()`, so `symlink/receipt.json` is absent from
   `fixture_files` (`receipt.json present for symlink arm? False`). The arm input remains pinned
   indirectly — the fixture's `.git/index` (mode `120000`) and the object store (11 objects, incl.
   blob `8b38e5de…` = `allowed.txt`) *are* digested, and the sealed builder pins the arm's
   construction — so the arm is reproducible and integrity-checkable, but the manifest alone does not
   name the symlink.
3. **Pre-existing, C1-invisible, and documented:** `scan()` ignores the tree entry mode, so a
   committed symlink's *target text* is scanned as if it were file content (the r22 knowledge note
   states this deliberately: "Every tracked blob is scanned, including stored symlink target bytes"),
   while `committed()` refuses non-regular blobs for receipt/policy/allowlist ("Input files
   themselves must be regular committed blobs"). R21 exercises only the input side. The r23 fixture's
   symlink arm exits before scanning, so no C1 requirement — and no recorded measurement — is
   affected. No change proposed; flagged so it is not mistaken for a C1 regression.
4. **C2 red is unrelated to R21.** `C34`/`C30` are false because of the frozen `CaseEscapedSpace`
   contradiction; the C1 denominator (26) and the supplementary guards are unaffected. Do not merge
   the two axes; the C1 claim stands on its own denominator.
5. **Open debt unchanged** (four unallowlisted inherited hits, original permission RED 11/12, two
   unknown dispositions, baseline acceptance blocked, `privacy_clearance=false`). Nothing in this
   review clears, promotes or admits anything; probe visibility is not clearance.
