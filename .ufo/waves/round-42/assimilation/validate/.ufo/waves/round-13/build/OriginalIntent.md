# Round 13 legacy contract reconstruction — F01 / F02

**Axes:** coverage and operability. **Scope:** the two legacy defects only; this is a reconstruction, not a remediation or a claim about the separate journal-scope work. No tests or runtime checks were run for this report, and no tools were installed.

## Reconstructed contract

### F01 — post-launch subject authorship

The lane’s row-A condition is an exact author identity in a strict committer-time window, not merely a recent commit or a matching committer. The census requests Git rows in the shape `%ct %an <%ae>`; it then keeps rows whose numeric `%ct` is strictly greater than the launch epoch and no later than `NOW_EPOCH` (`tools/mori-census.sh:1473-1491`). It removes the timestamp prefix and uses `grep -Fxq` against the whole identity string `$lane-shokunin <$lane@shokunin.local>` (`:1492-1498`). The driver’s stated interface independently records both exact identity fields and the launch-window boundary (`tools/mori-silence-cases.sh:107-130`).

For lane `kagi`, therefore, the positive record is exactly `1699999000 kagi-shokunin <kagi@shokunin.local>` when launch is `1699998000` and `NOW_EPOCH=1700000000`. A different author name or email is not a subject match. The intended grade is `progressing` / row-A (`subject_commits=yes`); sibling-only post-launch activity is `progressing-weak` / row-C, not row-A (`tools/mori-census.sh:1502-1535`; oracle historical cases also distinguish the two, `corpus/evidence/backchannel-r6-20261015T191216Z-selftest.log:36-43`).

### F02 — normal census roll

The existing public roll shape is `MORI_CENSUS: CLEAN|DRIFT (findings=N drift=M unavailable=U surfaces=S)` and the corresponding normal-run exit mapping is `CLEAN → 0`, `DRIFT → 1`; setup/usage failures use exit 2 (`tools/mori-census.sh:7-8,352-353,1733-1740`). This is the contract to check, not a proposal to add a new command or alter output.

The tally fields have distinct meanings in the implementation (`tools/mori-census.sh:328-381,1551-1571,1733-1740`): `findings` counts all finding rows; `drift` counts warning/critical findings, and only those severities set `ROLL=DRIFT`; informational findings may coexist with `CLEAN`. `unavailable` counts unavailable *top-level* surface states, and `surfaces` counts top-level `emit_surface` calls. Per-lane `SURFACE lane.<id>` rows are appended separately and explicitly are not counted as extra surfaces (`:1562-1571`). A tally check must preserve that distinction.

## Evidence chain and divergences

- **R9 fixed a harness race, not this production race.** The r9 note documents `grep -q` closing a live pipe early, `pipefail` exposing producer SIGPIPE as a nonzero pipeline result, and a false assertion result (`corpus/knowledge/selftest-flake-r9.md:31-42`). Its site inventory separately identifies the production `printf | sed | grep -Fxq` in the silence path as a wrong-grade risk (`:116-129`). The r9 fix captured selftest output to a file and changed harness-only checks; it explicitly says production code was untouched and the production site remained open debt (`:155-184,260-264`; `.ufo/reports/round-9/mori-goalwave.md:16-21`).
- **F01’s observed defect is the same conditional inversion at scale.** The current production path runs the exact author match through `printf | sed | grep -Fxq` under `set -euo pipefail` (`tools/mori-census.sh:236,1490-1498`). The r11 Appendix B quiet fixture supplied one in-window exact subject row followed by 12,000 sibling rows through the documented `MORI_GIT_BIN` override. It expected `progressing`; the recorded result was `progressing-weak`, `basis=row-C other_authored_commits=12001`, rc 0 (`corpus/knowledge/audit-r11.md:308-374`, especially `:333-369`). A successful early grep can be outweighed by an upstream SIGPIPE under `pipefail`; the `if` then takes its false branch and leaves the sibling-only grade. This is a synthetic history reproducing the data shape, not a claim about any real lane’s history.
- **R10 did not close either F01 or F02.** Its work added pin/drift behavior while leaving the default census run/emission path unchanged; the note says no `run_census`/`emit_*` edit was made (`corpus/knowledge/drift-pin-r10.md:45-65,74-83`). Its oracle was recorded as byte-frozen, and the round report describes default output as unchanged (`.ufo/reports/round-10/mori-goalwave.md:15-22,24-32`). R10’s exit contract does not supply the missing oracle assertion.
- **F02 is an oracle assertion gap, not a lane-grade failure.** The driver documents its existing public invocation as `mori-silence-cases.sh [path-to-census]` (`tools/mori-silence-cases.sh:6-9`). `assert_case` captures only the first line beginning `MORI_CENSUS:`; it fails if that line is absent, then independently checks expected lane state, `LANE_SILENT`, census rc, and nonce (`:555-617`). It does not validate the roll token, the roll/rc relation, or the tally fields. The exact r11 Appendix C wrapper invokes the real census, replaces only `CLEAN`/`DRIFT` with `BANANA`, preserves output rows and original rc, and was accepted as `matched=28 total=28` (`corpus/knowledge/audit-r11.md:376-396`; defect summary `:156-157`). Thus the current oracle accepts an invalid roll even while its lane-state checks remain green.

## Faithful regression recommendations

1. **F01 positive long-history case:** preserve the Appendix B shape and fixtures: fixed launch/NOW, one exact in-window subject identity row first, then 12,000 in-window sibling-identity rows, delivered through the already documented Git override rather than real host history. Keep the complete row grammar `%ct %an <%ae>` and the exact lane identity. Require row-A `progressing` / `subject_commits=yes`, no `LANE_SILENT`, and rc 0. This is the direct counterexample; ordinary short histories are not a negative control for it (Appendix B: `:310-313,333-369,372-374`).
2. **F01 sibling-only negative:** use the same long-window volume and timestamps but omit the exact subject identity; require row-C `progressing-weak` and the sibling count. Pairing this with the positive guards against a blunt “large history means progressing” change. This positive/negative pair is also the audit’s explicit next falsifier for F01 (`corpus/knowledge/audit-r11.md:196`).
3. **F02 invalid-word and mismatched-roll cases:** retain the existing optional census-path argument and per-case lane/finding/nonce assertions. Use the Appendix C proxy pattern: mutate only the final roll token to `BANANA`, preserving all lane rows, nonce, and rc, and require a case failure. Separately flip only a valid `CLEAN`/`DRIFT` token while preserving the original rc; both directions must fail. These target the observed hole without weakening the earlier lane-state/run-order cases (`audit-r11.md:157,376-396`; `tools/mori-silence-cases.sh:555-617`).
4. **F02 tally integrity:** mutate one summary number while leaving rows and rc intact, and require failure. Validate the documented complete roll grammar plus recompute its existing totals from the emitted top-level rows: all finding lines; warning/critical findings for `drift`; top-level unavailable surfaces for `unavailable`; and top-level surfaces only for `surfaces` (exclude per-lane rows). Do not equate nonzero `findings` with `DRIFT`, because informational findings do not set the roll (`tools/mori-census.sh:360-381,1562-1571,1733-1740`). This specifically covers the audit’s named tally-corruption falsifier (`corpus/knowledge/audit-r11.md:197`).

## Confidence and limits

**High confidence** in the reconstructed contracts and defect mechanisms: exact source branches, the existing driver contract, and the r11 Appendix B/C recorded counterexamples agree. **Bounded evidence:** Appendix B’s one synthetic long-history witness and Appendix C’s wrapper result do not establish that every long history fails or that every possible invalid oracle response is accepted. The recommendations target these witnessed classes and the documented output/CLI contract only; they do not claim general anti-forgery coverage.
